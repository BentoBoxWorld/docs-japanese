# Upgrades

**Upgrades** はプレイヤーにアイランドのアップグレードを購入することで進行の達成感を与えます。保護範囲の拡大、ブロック/エンティティ制限の引き上げ、カスタムコマンド、スポーナーブースト、作物成長ブーストをお金、アイテム、権限、またはアイランドレベルを使用して購入できます。

作成・メンテナンス: [tastybento](https://github.com/tastybento)

{{ addon_description("Upgrades", true) }}

!!! warning "警告: バージョン 1.0.0 は完全な書き直しです"
    Upgrades 1.0.0 は古い設定ファイルベースのシステムを完全な**データベース駆動アーキテクチャ**に置き換えました。アップグレードの定義、ティア、価格、報酬は現在 BentoBox のデータベースに保存され、すべてゲーム内で管理されます。**古い `config.yml` はアップグレード定義をもう行いません** — 0.x からアップグレードする場合は 1.0.0 をインストールする前に削除してください。生成される 1.0.x ファイルはいくつかの設定のみを保持します。[`config.yml` がまだ行うこと](#configymlがまだ行うこと) を参照してください。

## インストール

1. Upgrades アドオンの jar を BentoBox プラグインの addons フォルダに配置します。
2. サーバーを再起動します。
3. 初回起動時に 8 つのサンプルアップグレードが自動的にシードされます。
4. `/[admin_command] upgrade` を使用してゲーム内でアップグレードをカスタマイズまたは作成します。

## 仕組み

アップグレード、ティア、価格、報酬は BentoBox のデータベース（YAML、JSON、MySQL、MongoDB など）に保存されます。編集が必要な大きな設定ファイルはありません。すべてのアップグレードデータはアドオンによって自動的に読み込み、キャッシュ、保存されます。

初回インストール時にシーダーが 8 つのサンプルアップグレードを作成します。サンプルアップグレードを削除すると、次の再起動時に再シードされません。シードを再トリガーするには、アドオンのデータフォルダから `.seeded-gamemodes` マーカーファイルを削除してください。

### `config.yml` がまだ行うこと

!!! info "1.0.4 以降"
    `config.yml` は当初からアップグレードは**ここでは定義されない**と述べ、古い設定駆動システムの不活性な `range-upgrade`、`command-upgrade`、`entity-icon`、`entity-group-icon`、`command-icon` セクションが削除されました。最新ファイルは [こちら](https://github.com/BentoBoxWorld/Upgrades/blob/develop/src/main/resources/config.yml) です。

    3 つのセクションはまだ読み込まれます — `block-limits-upgrade`、`entity-limits-upgrade`、`entity-group-limits-upgrade` — しかしアップグレード**作成しません**。どの制限が Upgrades に属しているかを Upgrades に伝えるため、Limits アドオン独自のパーミッションベースの制限が抑制され、2 つが同じ制限で競合しません。**キー名のみが重要**（`HOPPER`、`CHICKEN`、`group1` など）；その下のティア値は無視されていますが、古いファイルがまだロードされるため保持されます。ゲームモードごとに `gamemodes:` ブロックでセットを上書きできます。

    `disabled-gamemodes`（Upgrades が非アクティブなゲームモード）と `chat-input-escape`（管理者パネルのチャットプロンプトをキャンセルする文字列、デフォルト `END`）も引き続き適用されます。古いファイルの他のすべては不活性で削除できます。既存のファイルはアップグレード時に上書きされません。

    🔺 1.0.4 以前、`entity-limits-upgrade` エントリは削除された `entity-icon` セクションにも同じエンティティが表示されている場合のみ有効でした。エンティティエントリは独自に有効になるようになりました — マッチング アイコンなしでリストされたエンティティがあった場合、その Limits パーミッションが以前は抑制されなかったため抑制されるようになりました。

## ティアとレベル

各アップグレードは 1 つ以上の**ティア**で構成されています。ティアはレベルの範囲をカバーします。例えば、あるティアがレベル 0〜4 をカバーする場合、その範囲内のアップグレードレベルを持つプレイヤーはそのティアの報酬の対象となります。

- プレイヤーがアップグレードを購入するたびにレベルが 1 上がります。
- 購入パネルは各アップグレードの進捗をアイテムロア内に表示します（例：`Level: 2 / 5` — アイランドの現在のレベルと、そのティアで許可されている最高レベル）。この行は `upgrades.ui.upgradepanel.currentlevel` ロケールキーでスタイル設定されます。キーを空白にするとこの行を非表示にします。*（1.0.5 以降。）*
- 適用される報酬は常にプレイヤーの現在のレベルを含むティアの報酬です。新しいティアの範囲に入ると即座にそのティアの報酬に切り替わります。
- 1 つのティアに**複数の価格**（すべて支払う必要あり）と**複数の報酬**（すべて適用）を設定できます。
- 価格と報酬のフォーミュラは変数（[フォーミュラ変数](#フォーミュラ変数) 参照）を使用して、レベル、アイランドレベル、またはチームサイズに応じて自動的にスケールできます。

## コマンド

!!! tip "ヒント"
    `[player_command]` と `[admin_command]` は実行中のゲームモードによって異なるコマンドです。

=== "プレイヤーコマンド"
    - `/[player_command] upgrade`: アップグレード購入パネルを開きます。

=== "管理者コマンド"
    - `/[admin_command] upgrade`: アップグレードとティアの作成、編集、削除ができる管理者 GUI を開きます。

## 価格タイプ

各アップグレードティアは以下の価格の任意の組み合わせを必要とします（購入するにはすべての条件を満たす必要があります）:

| タイプ | 説明 |
|---|---|
| **Money** | Vault エコノミーコスト |
| **Items** | プレイヤーのインベントリに特定のアイテムが必要 |
| **Permissions** | プレイヤーが特定の権限ノードを持っている必要がある |
| **Island Level** | 最小アイランドレベル（Level アドオンが必要） |

## 報酬タイプ

各アップグレードティアは以下の報酬の任意の組み合わせを付与できます:

| タイプ | 説明 | 適用タイミング |
|---|---|---|
| **Range** | アイランド保護範囲を拡大します | 購入時 |
| **Block Limits** | ブロックタイプのアイランドごとの制限を引き上げます（Limits アドオンが必要） | 購入時 |
| **Entity Limits** | エンティティタイプの制限を引き上げます（Limits アドオンが必要） | 購入時 |
| **Entity Group Limits** | エンティティグループの制限を引き上げます（Limits アドオンが必要） | 購入時 |
| **Commands** | 購入時にコンソールまたはプレイヤーコマンドを実行します | 購入時 |
| **Spawner Boost** | アイランド上のすべてのスポーナーイベントに追加スポーンを加えます | 常時パッシブ |
| **Crop Growth Boost** | アイランド上のすべての自然な作物成長イベントに追加成長ティックを加えます | 常時パッシブ |

### ブロック、エンティティ、エンティティグループの制限

3 つの制限報酬はすべて**同じ報酬エディター**を使用し、アップグレード購入時にアイランドごとの制限を引き上げられます。これらには [Limits](../Limits/index.md) アドオンが必要です。アドオンがないと報酬は何も行いません。

!!! info "Upgrades は基本制限に*加算*します — 制限値を設定するわけではありません"
    ブロック、エンティティ、グループの**基本（初期）制限**は、ここではなく **Limits アドオン**で設定します。制限報酬はその基本値の上に**オフセット**を加えるだけです。レベルを 1 つ購入するごとに報酬の数値が再び加算されるため、プレイヤーの実効制限は `Limits アドオンの基本値 +（アップグレードのオフセットの合計）` になります。

    例: Limits アドオンがホッパーの上限を `8` に設定し、プレイヤーが 1 レベルごとにホッパーを `1` 増やすアップグレードを 3 レベル購入した場合、そのアイランドには `8 + 3 = 11` 個のホッパーを設置できます。

#### 制限報酬の設定

1. `/[admin_command] upgrade` を実行して管理者 GUI を開き、アップグレードを作成または選択します。
2. アップグレードを開き、**ティア**を追加し（アップグレードには少なくとも 1 つのティアが必要です）、そのティアを開いて**報酬**をクリックします。
3. 新しい **Limits** 報酬（バリアアイコン）を作成します。報酬エディターには 3 つの設定があります:

| 設定 | 機能 |
|---|---|
| **Type（タイプ）** | クリックして `BLOCK`、`ENTITY`、`ENTITY_GROUP` を切り替えます。ホッパーなどのブロックを制限するには `BLOCK` を選択します。 |
| **Target（対象）** | 制限する対象。チャットで入力します。`BLOCK` には Bukkit の [Material](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/Material.html) 名（例: `HOPPER`、`CHEST`）、`ENTITY` には [EntityType](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/entity/EntityType.html) 名（例: `CHICKEN`）、`ENTITY_GROUP` には **Limits アドオンで定義されたグループに一致する**グループ名を使用します。 |
| **Amount（量）** | **レベルごと**に制限を引き上げる量。単純な数値、または[フォーミュラ変数](#フォーミュラ変数)を使用した式（例: `1`、または `[level] * 2`）を受け付けます。 |

報酬エディターの緑色のペインは設定が有効であることを示し、赤色のペインは必須フィールド（通常は Target）がまだ不足していることを示します。

4. `config.yml` の一致するセクション（`block-limits-upgrade`、`entity-limits-upgrade`、`entity-group-limits-upgrade`）の下に同じ Target をリストアップして、Limits アドオン独自のパーミッションベースの制限が抑制されます — [config.yml がまだ行うこと](#configymlがまだ行うこと)を参照してください。

!!! tip "ヒント: 異なるブロックには異なるアップグレードまたはティアが必要です"
    各制限報酬は単一のブロック/エンティティ/グループを対象とします。複数のブロックタイプの制限を引き上げるには、それぞれに個別の制限報酬を追加し（同じティア上の複数の報酬として、または別々のアップグレードとして）、それぞれに独自の Target を設定します。

### Commands（コマンド）

Commands 報酬はプレイヤーがアップグレードを購入したときに 1 つ以上のコマンドを実行します。

- **コンソールモード**: コマンドはサーバーコンソールとして実行されます（`/give`、ランク昇格コマンド、高い権限が必要なコマンドに使用してください）。
- **プレイヤーモード**: コマンドはアップグレードを購入したプレイヤーとして実行されます（そのプレイヤーの権限に制限されます）。

コマンド文字列では以下のプレースホルダーが使用できます:

- `[player]` — アップグレードを購入したプレイヤーの名前
- `[owner]` — アイランドオーナーの名前

### Spawner Boost（スポーナーブースト）

スポーナーブーストは**パッシブな常時有効**効果です。購入時には何も起こりません。即座に有効になり、アイランドがそのアップグレードレベルを保持している間は常に有効です。

アイランド上のスポーナーが起動するたびに、アドオンはすべての有効なアップグレードティアにわたるアイランドの合計スポーナーブースト値を計算し、同じ場所に同じタイプのモブをその数だけ追加スポーンさせます。

フォーミュラ値は**ボーナス倍数**です:

| フォーミュラ値 | スポーナーイベントごとの効果 |
|---|---|
| `0.5` | 50% の確率で追加モブ 1 体 |
| `1.0` | 常に追加モブ 1 体 |
| `1.5` | 常に追加モブ 1 体 + 50% の確率でさらに 1 体 |
| `2.0` | 常に追加モブ 2 体 |

スポーナーブースト報酬を含む複数のアップグレードのボーナスは**加算**されます。すべてのスポーナータイプで機能します。

### Crop Growth Boost（作物成長ブースト）

作物成長ブーストも**パッシブな常時有効**効果です。作物が自然に成長するとき、アドオンはボーナス値に等しい追加の骨粉成長ティックを適用します。プレイヤーのアップグレードレベルが高いほど、作物の成長が速くなります。

フォーミュラ値はスポーナーブーストと同様に機能します:

| フォーミュラ値 | 自然成長イベントごとの効果 |
|---|---|
| `0.5` | 50% の確率で追加成長ティック 1 回 |
| `1.0` | 常に追加成長ティック 1 回 |
| `2.0` | 常に追加成長ティック 2 回 |

複数のアップグレードのボーナスは加算されます。対応作物: **小麦、ニンジン、ジャガイモ、ビートルート、ネザーウォート、スイートベリーブッシュ、トーチフラワー、ピッチャープラント**。

## フォーミュラ変数

価格と報酬の両方のフォーミュラフィールドで以下の変数が使用できます:

- `[level]` — 購入中（または有効）の現在のアップグレードレベル
- `[islandLevel]` — アイランドの現在のレベル（Level アドオンから; Level がインストールされていない場合は 0 の可能性あり）
- `[numberPlayer]` — アイランドチームのプレイヤー数

これらの変数を使用すると自動的にスケールするフォーミュラを書くことができます。例えば、お金のコスト `500 * [level]` やスポーナーボーナス `0.1 * [level]` などです。

## 権限

権限はアップグレード設定に基づいてアドオンが自動的に付与します。現在の権限リストは [addon.yml](https://github.com/BentoBoxWorld/Upgrades/blob/develop/src/main/resources/addon.yml) を確認してください。

## API

`UpgradeAPI` クラスは他のアドオンがプログラムでアップグレードデータを照会および変更するために公開されています。上記のアドオン説明からリンクされた JavaDocs を参照してください。
