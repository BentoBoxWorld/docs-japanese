# Greenhouses

Greenhouses はアイランドワールドをパワーアップする BentoBox アドオンです！プレイヤーが天気、友好的なモブのスポーン、独自の植物成長、さらにはブロックの侵食を備えた自分だけのバイオームグリーンハウスを建てられるようにします！

グリーンハウスはガラスで作られており、有効であるためにはバイオームレシピに含まれるブロックを含む必要があります。レシピの GUI があります。作成後、グリーンハウスでは骨粉を使って植物を育てることができ、バイオーム固有のモブがスポーンすることがあります。水の入ったホッパーを含める場合、雨が降るときにグリーンハウス内に雪が降ります。ホッパーに骨粉を入れると、バイオーム固有の植物が育ちます。一部のブロックは「侵食」によって時間の経過とともに変化することもあります。

作成・メンテナンス: [tastybento](https://github.com/tastybento)

## 機能

* アイランド（または好みであれば他の場所）に自己完結型のバイオームグリーンハウスを作る
* グリーンハウスでは通常育てられないヒマワリなどの植物も育てられます
* グリーンハウスが上手く設計されていれば友好的なモブがスポーンします - スライムが欲しいですか？沼地のグリーンハウスを作りましょう！
* ブロックはバイオームに応じて時間の経過とともに変化します - 砂漠では土が砂になり、川では土が粘土になるなど。
* グリーンハウスは複数のワールドで動作できます。
* 使いやすい GUI でグリーンハウスのレシピを表示します（例: **/is greenhouses**）
* 管理者はバイオームとレシピを完全にカスタマイズできます

## グリーンハウスの建て方

この例は BSkyBlock ワールドでの操作です。AcidIsland では /island の代わりに /ai を使用してください。

1. ガラスブロックを作成し、平らな屋根を持つ長方形の壁を建てます。
2. 壁または屋根にホッパーを設置します。
3. 中に入ったり出たりできるようにドアを壁に設置します。
4. **/island greenhouses** と入力し、希望するグリーンハウスのルールを読みます。
5. GUI を閉じてブロック、水、溶岩、氷を配置して目的のバイオームを作ります。
6. **/island greenhouses** を再び入力してバイオームを作るためにクリックします。
7. **/island greenhouses help** と入力して他のオプションを確認します。

### 作成後:

* グリーンハウス内の草ブロック上の小さな植物をすぐに骨粉で育てます。
* またはホッパーに骨粉を入れて、グリーンハウスが自動的に骨粉を撒くようにします。後で戻って何が育ったか確認しましょう！
* ホッパーにバケツ一杯の水（または複数）を入れると、寒いバイオームで雪が降るようになります。ワールドで雨が降ると雪が降ります。一度の降雪で水バケツ一つが消費されます。
* バイオーム固有の友好的なモブがグリーンハウスにスポーンすることがあります - 通常のルールが適用されます（24ブロック以上離れている必要があります）。

## よくある質問

* 色付きガラスを使えますか？ はい、使えます。きれいですよ。
* グリーンハウスを水で満たせますか？ はい。それは海になります。
* スイカがそこにスポーンしますか？ たぶん...実際にはそうです、十分に大きな海であれば。
* 壁が全部ガラスなのに、壁の高い位置にドアを設置するにはどうすれば？ ホッパーの上に設置してください。
* ホッパーにドアを設置するには？ しゃがんでから設置してください。
* 金属ドアを使えますか？ はい。
* トラップドアを使えますか？ はい。
* これで沼地の花を育てられますか？ はい。沼地バイオームを作って骨粉を使ってください。
* 植物を育てるのにどれくらいの骨粉が使われますか？ 植物が成功して育つごとに1本。
* ホッパーに雪を降らせるのにどれくらいの水が必要ですか？ 雨が降るたびにバケツ一杯の水（水だけ）が消費されます。これは寒いバイオームでのみ起こります。
* ネザーグリーンハウスを建てられますか？ 試してみてください...（実際には権限が必要かもしれません）
* ネザーにグリーンハウスを建てられますか？ はい。それらを使ってネザーを植民地化できます。
* バイオームにはどんなモブがスポーンしますか？ 予想通りのものです。寒い針葉樹林ではオオカミ、平原では馬など。

## 必要プラグイン

このバージョンの Greenhouses は BentoBox のアドオンであり、スタンドアロンでは動作しません！

1. BentoBox - 最新バージョンを使用していることを確認してください！

## インストールと設定

1. BentoBox をダウンロードしてインストールします（まだの場合）
2. アドオンをダウンロードします
3. BentoBox の addons フォルダに配置します
4. サーバーを再起動します
5. アドオンは greenhouses というデータフォルダを作成します。そのフォルダを開きます。
6. **config.yml** を確認して希望通りに編集します。ワールド名のリストに注意してください。
7. 必要であれば **biomes.yml** を設定します（上級者向け）。
8. ゲーム内で **/bsbadmin greenhouses reload** と入力して設定をリロードするか、サーバーを再起動します。
9. 完了！

最初のグリーンハウスを作るには、ガラスの箱を建てて **/is greenhouses make** と入力して、どんなグリーンハウスになるか確認してください。**/is greenhouses** と入力してレシピを確認してください。

## プレイヤーコマンド

/island、/ai に以下のコマンドを追加します。コマンドラベルは `greenhouse` で、エイリアスは `gh` と `greenhouses` です。

* **greenhouses** - レシピ GUI を開きます。レシピをクリックするとそのグリーンハウスを作ろうとします
* **greenhouses help** - これらのコマンドの一覧を表示します
* **greenhouses make [recipe]**: 最初に有効なレシピを見つけて、または指定したレシピを使ってグリーンハウスを作ろうとします
* **greenhouses remove**: 立っているグリーンハウスを（オーナーであれば）削除します

!!! warning "`list` と `recipe` は 1.10.0 で削除されました"
    この 2 つのプレイヤーコマンドはドキュメントに記載されていましたが、実際には一度も登録されていませんでした — 到達不能なスタブであり、実行しても不明なコマンドのエラーが出るだけでした。これらは 1.10.0 で削除されました。引数なしの `/is greenhouses` がレシピ GUI を開きます。これが本来これらのコマンドが行うはずだったことです。

## 管理者コマンド

!!! new "Greenhouses 1.10.0 で追加"
    1.10.0 より前は、このアドオンに管理者コマンドツリーはまったく存在しませんでした。グリーンハウスのレコードが壊れた場合、サーバーを停止してデータベースを手作業で編集するしかありませんでした。

ゲームモードの管理者コマンドの配下に登録されます（例: `/bsbadmin greenhouses` や `/acid greenhouses`）。ラベルは `greenhouses` で、エイリアスは `greenhouse` と `gh` です。

| コマンド | 動作 |
|---|---|
| `list [player] [page]` | グリーンハウスをページ分割して一覧表示します。特定のプレイヤーのものだけに絞ることもできます。読み込みに失敗したレコードも**必ず**理由付きで一覧に表示されます。 |
| `info [id]` | レシピ、オーナー、ワールド、位置、バウンディングボックス、面積、元のバイオーム、ホッパー、破損状態、不足しているブロックを表示します。ID を省略すると、現在立っているグリーンハウスが対象になります。 |
| `delete <id>` | 確認を求めたうえで、読み込み済みかどうかにかかわらずレコードを削除します。 |
| `tp <id>` | グリーンハウスの床の中央にテレポートします。エイリアス: `teleport`。 |
| `verify [id]` | 1 つまたはすべてのグリーンハウスをレシピと照合して再チェックし、不足しているものを報告します。エイリアス: `check`。 |
| `reload` | `biomes.yml` を読み直し、その後データベースからグリーンハウスを再読み込みします。 |

- ID は `list` で取得でき、**1 つだけ**にマッチする接頭辞であれば短縮できます。曖昧な接頭辞は推測せずマッチなしとして扱われます。間違ったグリーンハウスを削除すると元に戻せないためです。
- `tp` 以外はすべてサーバーコンソールから実行できます。
- 読み込めないグリーンハウスのレコード — 重複、不明なレシピ、ワールドの欠落、位置なし — は、黙って破棄されるのではなく理由とともにメモリ上に保持されます。これにより一覧表示や削除が可能になっています。
- レコードが自動的に削除されることはありません。断りなくプレイヤーのグリーンハウスを削除するのは、警告が繰り返し出続けるより悪いことだからです。

!!! tip "重なり合ったグリーンハウス"
    保存されている 2 つのグリーンハウスが重なっている場合、起動時に一方がスキップされ、重なっている相手のレコードとともにログに記録されます。`/bsbadmin greenhouses list` でスキップされたレコードとその理由を確認し、`/bsbadmin greenhouses delete <id>` で不要な方を削除してください。データベースの編集も再起動も不要です。

## 権限 { #permissions }

権限の完全なリストは[こちら](Permissions)にあります。

特定のバイオームを使用する権限は biomes.yml で追加できます。

例えば、ネザーバイオームの権限は **greenhouses.biome.nether** であり、ここで設定されています:

 NETHER:

    permission: greenhouses.biome.nether

権限はランク権限 **myserver.VIP** など、任意のものを設定できます。

### 一般権限:

  greenhouses.player:

     description: プレイヤーコマンドへのアクセスを付与します
     default: true

  greenhouses.admin:

     description: 管理者コマンドへのアクセスを付与します
     default: op

1.10.0 以降は、各管理者サブコマンドにも個別のノード — `greenhouses.admin.list`、`.info`、`.delete`、`.tp`、`.verify`、`.reload` — があり、いずれもデフォルトは `op` です。オペレーターは何もする必要はありませんが、権限管理プラグインで管理者アクセスを付与している場合はこれらを追加する必要があります。このリリースより前は `addon.yml` にこれらが完全に欠けており、そのため op によるアクセス以外は機能しませんでした。

    **リリース日:** 2026-07-26

    Greenhouses にようやく管理者コマンドツリーが加わりました。互換性: BentoBox API 2.7.1 · Minecraft 1.21.5+ · Java 21。

    - 🛠️ **管理者コマンド。** `list`、`info`、`delete`、`tp`、`verify`、`reload` が、ゲームモードの管理者コマンド（例: `/bsbadmin greenhouses`）の配下に登録されました。上記の「管理者コマンド」セクションを参照してください。読み込めないグリーンハウスのレコード — 重複、不明なレシピ、ワールドの欠落、位置なし — は、黙って破棄されるのではなく理由とともにメモリ上に保持されるようになり、これにより表示や削除が可能になりました。レコードが自動的に削除されることは、これまでどおりありません。
    - ⚙️ **新しい権限。** 6 つのサブコマンドにはそれぞれ `greenhouses.admin.*` 配下の独自のノードがあり、いずれもデフォルトは `op` です。このリリースより前は `addon.yml` にこれらが完全に欠けており、そのため op によるアクセス以外は機能しませんでした。
    - 🐛 **レシピが存在しなくなったグリーンハウスをチェックしても NPE が発生しなくなりました。** データベースのレコードが `biomes.yml` にないレシピを指している場合、チェックは `FAIL_UNKNOWN_RECIPE` を報告するようになりました。
    - 🐛 **位置を持たないレコードで `getFloorHeight` が例外を投げなくなりました** — 最も壊れている可能性が高いのは、まさにそうしたレコードです。バウンディングボックスにフォールバックします。
    - 🔺 **雪の処理が、走査したすべての列からの成功を報告するようになりました。** 最後の列だけではありません。`SnowTracker` は列ごとに結果を上書きしていたため、90 の列で雪を作りながら最後の 1 列で失敗したグリーンハウスは失敗と報告されていました — この値はホッパーから水を消費するかどうかを決めるものです。
    - 🧹 SonarCloud の未解決の 68 件の問題をすべて解消し、5 つのメソッドを認知的複雑度のしきい値以下にリファクタリング、デッドコードを削除し、テストスイートを 177 件から 224 件に増やしました。

    🔡 **翻訳者を募集しています。** 管理者コマンドにより `greenhouses.commands.admin.*` 配下にメッセージが追加されましたが、現在は英語のみです。他の 24 個のロケールファイルは、翻訳されるまでキー名にフォールバックします。

    🔺 **3 つのプレイヤーコマンドが削除されましたが、いずれも動作していませんでした。** `InfoCommand`、`ListCommand`、`RecipeCommand` は、中身がプレースホルダーの未登録スタブでした。`InfoCommand` に至っては自身を `make` というラベルで宣言しており、もし誰かが有効にしていたら本物の make コマンドと衝突していたはずです。このページでは以前 `greenhouses list` と `greenhouses recipe` を動作するプレイヤーコマンドとして掲載していましたが、それは誤りであり、修正しました。引数なしの `/is greenhouses` は引き続きレシピ GUI を開きます。

??? warning "v1.9.6 の新機能 — 重なり合ったグリーンハウスを診断できるように"
    **リリース日:** 2026-07-25

    - 🐛 **重なり合ったグリーンハウスを診断できるようになりました。** 保存されている 2 つのグリーンハウスが重なっている場合、起動時に一方がスキップされますが、以前のログ行は `Greenhouse overlaps with another greenhouse. Skipping...` としか出力せず、対処の手掛かりが何もないまま再起動のたびに繰り返されていました。警告は**両方**のレコードについて `uniqueId`、レシピ、オーナー、ワールド、位置、バウンディングボックスを示し、修正方法も伝えるようになりました。要約行は `Loaded 63 greenhouses out of 65 in the database.` のように表示され、末尾にスキップされた件数の集計が付きます。
    - 🔺 **グリーンハウスの読み込み順序が決定的になりました。** グリーンハウスはデータベースが返した順に読み込まれていたため、重なり合う 2 つのレコードのどちらが残るかは不定で、再起動のたびに入れ替わることもありました。読み込み前に `uniqueId` でソートされるようになったので、どちらかのレコードを削除するまで結果は安定します。
    - ⚙️ **`biomes.yml` の `OCEAN` レシピから重複した `SQUID` エントリを削除しました。** 2 回記載されていたため、新しいバージョンのサーバーでは SnakeYAML が重複キーの警告を出していました。YAML は最後の出現を採用するので、実効値（`20:WATER`）は保たれており、モブのスポーンに変更はありません。

    ⚙️ **`biomes.yml` の修正は自動的には適用されません。** サーバーにはすでに独自の `biomes.yml` がディスク上にあり、アドオンはそれを上書きしません。`SQUID` に関する SnakeYAML の重複キー警告が出る場合は、`plugins/BentoBox/addons/Greenhouses/biomes.yml` を開いて `OCEAN` セクションを探し、2 つある `SQUID:` 行のうち最初の 1 行を削除してください。新規インストールでは修正済みのファイルが自動的に配置されます。

    🔺 **このリリースは重なり合ったグリーンハウスを報告しますが、削除はしません。** スキップされたレコードは意図的にデータベースに残されます — プレイヤーのグリーンハウスを黙って削除するのは、警告が繰り返し出続けるより悪いことだからです。1.9.6 では、ログに出力されるようになった `uniqueId` を使って古いレコードを自分で削除する必要がありました。1.10.0 では、それをゲーム内で行える管理者コマンドが追加されています。
