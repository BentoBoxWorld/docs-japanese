# Greenhouses

Greenhouses はアイランドワールドをパワーアップする BentoBox アドオンです！プレイヤーが天気、友好的なモブのスポーン、独自の植物成長、さらにはブロックの侵食を備えた自分だけのバイオームグリーンハウスを建てられるようにします！

グリーンハウスはガラスで作られており、有効であるためにはバイオームレシピに含まれるブロックを含む必要があります。レシピの GUI があります。作成後、グリーンハウスでは骨粉を使って植物を育てることができ、バイオーム固有のモブがスポーンすることがあります。水の入ったホッパーを含める場合、雨が降るときにグリーンハウス内に雪が降ります。ホッパーに骨粉を入れると、バイオーム固有の植物が育ちます。一部のブロックは「侵食」によって時間の経過とともに変化することもあります。

作成・メンテナンス: [tastybento](https://github.com/tastybento)

{{ addon_description("Greenhouses") }}

## 機能

* アイランド（または好みであれば他の場所）に自己完結型のバイオームグリーンハウスを作る
* グリーンハウスでは通常育てられないヒマワリなどの植物も育てられます
* グリーンハウスが上手く設計されていれば友好的なモブがスポーンします - スライムが欲しいですか？沼地のグリーンハウスを作りましょう！
* ブロックはバイオームに応じて時間の経過とともに変化します - 砂漠では土が砂になり、川では土が粘土になるなど。
* グリーンハウスは複数のワールドで動作できます。
* 使いやすい GUI でグリーンハウスのレシピを表示します（例: **/is greenhouses**）
* 管理者はバイオームとレシピを完全にカスタマイズできます

## グリーンハウスの建て方

この例は BSkyBlock ワールドでの操作です。AcidIsland では /island の代わりに /ai を使用してください。

1. ガラスブロックを作成し、平らな屋根を持つ長方形の壁を建てます。
2. 壁または屋根にホッパーを設置します。
3. 中に入ったり出たりできるようにドアを壁に設置します。
4. **/island greenhouses** と入力し、希望するグリーンハウスのルールを読みます。
5. GUI を閉じてブロック、水、溶岩、氷を配置して目的のバイオームを作ります。
6. **/island greenhouses** を再び入力してバイオームを作るためにクリックします。
7. **/island greenhouses help** と入力して他のオプションを確認します。

### 作成後:

* グリーンハウス内の草ブロック上の小さな植物をすぐに骨粉で育てます。
* またはホッパーに骨粉を入れて、グリーンハウスが自動的に骨粉を撒くようにします。後で戻って何が育ったか確認しましょう！
* ホッパーにバケツ一杯の水（または複数）を入れると、寒いバイオームで雪が降るようになります。ワールドで雨が降ると雪が降ります。一度の降雪で水バケツ一つが消費されます。
* バイオーム固有の友好的なモブがグリーンハウスにスポーンすることがあります - 通常のルールが適用されます（24ブロック以上離れている必要があります）。

## よくある質問

* 色付きガラスを使えますか？ はい、使えます。きれいですよ。
* グリーンハウスを水で満たせますか？ はい。それは海になります。
* スイカがそこにスポーンしますか？ たぶん...実際にはそうです、十分に大きな海であれば。
* 壁が全部ガラスなのに、壁の高い位置にドアを設置するにはどうすれば？ ホッパーの上に設置してください。
* ホッパーにドアを設置するには？ しゃがんでから設置してください。
* 金属ドアを使えますか？ はい。
* トラップドアを使えますか？ はい。
* これで沼地の花を育てられますか？ はい。沼地バイオームを作って骨粉を使ってください。
* 植物を育てるのにどれくらいの骨粉が使われますか？ 植物が成功して育つごとに1本。
* ホッパーに雪を降らせるのにどれくらいの水が必要ですか？ 雨が降るたびにバケツ一杯の水（水だけ）が消費されます。これは寒いバイオームでのみ起こります。
* ネザーグリーンハウスを建てられますか？ 試してみてください...（実際には権限が必要かもしれません）
* ネザーにグリーンハウスを建てられますか？ はい。それらを使ってネザーを植民地化できます。
* バイオームにはどんなモブがスポーンしますか？ 予想通りのものです。寒い針葉樹林ではオオカミ、平原では馬など。
* 管理者がネザーグリーンハウスにウィザースケルトンが出現する可能性を追加するには？ `biomes.yml` の `NETHER` レシピにモブを追加してください — [モブスポーンのカスタマイズ](#モブスポーンのカスタマイズ例ウィザースケルトン)の下を参照。

このバージョンの Greenhouses は BentoBox のアドオンであり、スタンドアロンでは動作しません！

1. BentoBox - 最新バージョンを使用していることを確認してください！ Greenhouses 1.11.0 には BentoBox 3.24.0 以降、Paper 1.21.11 ～ 26.3、Java 25 が必要です。

## インストールと設定

1. BentoBox をダウンロードしてインストールします（まだの場合）
2. アドオンをダウンロードします
3. BentoBox の addons フォルダに配置します
4. サーバーを再起動します
5. アドオンは greenhouses というデータフォルダを作成します。そのフォルダを開きます。
6. **config.yml** を確認して希望通りに編集します。ワールド名のリストに注意してください。
7. 必要であれば **biomes.yml** を設定します（上級者向け）。
8. ゲーム内で **/bsbadmin greenhouses reload** と入力して設定をリロードするか、サーバーを再起動します。
9. 完了！

Greenhouses 1.11.0 で `config.yml` のオプションが 1 つ追加されました：

??? note "sample-ticks"
    Greenhouses 1.11.0 で追加。各グリーンハウス内で、モブのスポーンとブロック変換の対象となるランダムな場所を選ぶ頻度です（サーバーティック単位、20 = 1 秒）。値を小さくするほど処理がより均等に分散されます。全体の頻度は変わりません。全体の頻度は `mobtick` と `blocktick` で設定され、平均すると各場所には引き続き `mobtick` または `blocktick` ごとに 1 回の機会が与えられるため、モブは一度にまとめてではなく徐々に現れます。

    デフォルト：`20`

最初のグリーンハウスを作るには、ガラスの箱を建てて **/is greenhouses make** と入力して、どんなグリーンハウスになるか確認してください。**/is greenhouses** と入力してレシピを確認してください。

## プレイヤーコマンド

/island、/ai に以下のコマンドを追加します。コマンドラベルは `greenhouse` で、エイリアスは `gh` と `greenhouses` です。

* **greenhouses** - レシピ GUI を開きます。レシピをクリックするとそのグリーンハウスを作ろうとします
* **greenhouses help** - これらのコマンドの一覧を表示します
* **greenhouses make [recipe]**: 最初に有効なレシピを見つけて、または指定したレシピを使ってグリーンハウスを作ろうとします
* **greenhouses remove**: 立っているグリーンハウスを（オーナーであれば）削除します

!!! warning "`list` と `recipe` は 1.10.0 で削除されました"
    この 2 つのプレイヤーコマンドはドキュメントに記載されていましたが、実際には一度も登録されていませんでした — 到達不能なスタブであり、実行しても不明なコマンドのエラーが出るだけでした。これらは 1.10.0 で削除されました。引数なしの `/is greenhouses` がレシピ GUI を開きます。これが本来これらのコマンドが行うはずだったことです。

## 管理者コマンド

!!! new "Greenhouses 1.10.0 で追加"
    1.10.0 より前は、このアドオンに管理者コマンドツリーはまったく存在しませんでした。グリーンハウスのレコードが壊れた場合、サーバーを停止してデータベースを手作業で編集するしかありませんでした。

ゲームモードの管理者コマンドの配下に登録されます（例: `/bsbadmin greenhouses` や `/acid greenhouses`）。ラベルは `greenhouses` で、エイリアスは `greenhouse` と `gh` です。

| コマンド | 動作 |
|---|---|
| `list [player] [page]` | グリーンハウスをページ分割して一覧表示します。特定のプレイヤーのものだけに絞ることもできます。読み込みに失敗したレコードも**必ず**理由付きで一覧に表示されます。 |
| `info [id]` | レシピ、オーナー、ワールド、位置、バウンディングボックス、面積、元のバイオーム、ホッパー、破損状態、不足しているブロックを表示します。ID を省略すると、現在立っているグリーンハウスが対象になります。 |
| `delete <id>` | 確認を求めたうえで、読み込み済みかどうかにかかわらずレコードを削除します。 |
| `tp <id>` | グリーンハウスの床の中央にテレポートします。エイリアス: `teleport`。 |
| `verify [id]` | 1 つまたはすべてのグリーンハウスをレシピと照合して再チェックし、不足しているものを報告します。エイリアス: `check`。 |
| `reload` | `biomes.yml` を読み直し、その後データベースからグリーンハウスを再読み込みします。 |
| `edit [recipe]` | [レシピエディター](#in-game-recipe-editor)を開きます。レシピを指定した場合はそのレシピのエディターを開きます。1.11.0 以降。 |
| `build <recipe> [x y z] [WxDxH] [keep\|clear]` | レシピの[テストグリーンハウス](#test-greenhouse-builder)を、自分の周り、または指定した床の中心位置に建設します。1.11.0 以降。 |

- ID は `list` で取得でき、**1 つだけ**にマッチする接頭辞であれば短縮できます。曖昧な接頭辞は推測せずマッチなしとして扱われます。間違ったグリーンハウスを削除すると元に戻せないためです。
- `tp`、`edit`、`build` 以外はすべてサーバーコンソールから実行できます。
- 読み込めないグリーンハウスのレコード — 重複、不明なレシピ、ワールドの欠落、位置なし — は、黙って破棄されるのではなく理由とともにメモリ上に保持されます。これにより一覧表示や削除が可能になっています。
- レコードが自動的に削除されることはありません。断りなくプレイヤーのグリーンハウスを削除するのは、警告が繰り返し出続けるより悪いことだからです。

!!! tip "重なり合ったグリーンハウス"
    保存されている 2 つのグリーンハウスが重なっている場合、起動時に一方がスキップされ、重なっている相手のレコードとともにログに記録されます。`/bsbadmin greenhouses list` でスキップされたレコードとその理由を確認し、`/bsbadmin greenhouses delete <id>` で不要な方を削除してください。データベースの編集も再起動も不要です。

### 管理者ハブ { #admin-hub }

*Greenhouses 1.11.0 で追加されました。*

引数なしで `/bsbadmin greenhouses` を実行すると、すべての管理者ツールを使える GUI が開きます。コンソールから実行した場合は、これまでどおりヘルプが表示されます。ハブには次のボタンがあります：

- **レシピ**：レシピエディターを開きます。
- **グリーンハウス**：グリーンハウスブラウザーを開きます。
- **テストグリーンハウスを建設**：自分が立っている場所にテストグリーンハウスを建設します。
- **すべてのグリーンハウスをチェック**：すべてのグリーンハウスを再チェックします。
- **リロード**：確認のあとでリロードします。

各ボタンは、対応するサブコマンドの権限を持っている場合にのみ表示されます。ボタンは手入力するのと同じコマンドを実行するため、権限チェックやメッセージも同じです。

ブラウザーには、読み込みに失敗したものも含めてすべてのグリーンハウスが一覧表示され、オーナーで絞り込むことができます。ブラウザーでの操作：

| クリック | 動作 |
|---|---|
| 左クリック | そのグリーンハウスにテレポートします |
| 右クリック | そのグリーンハウスをチェックします |
| Shift クリック | 詳細を表示します |
| ++q++ | 確認ダイアログのあとで削除します |

### ゲーム内レシピエディター { #in-game-recipe-editor }

*Greenhouses 1.11.0 で追加されました。*

`/bsbadmin greenhouses edit [recipe]`（権限 `[gamemode].greenhouses.admin.edit`）を使うと、`biomes.yml` を編集したりサーバーを再起動したりせずに、バイオームレシピの作成、編集、複製、削除ができます。レシピのあらゆる部分を変更できます：

- アイコン、名前、説明
- バイオーム、優先度、権限
- 水、溶岩、氷の割合
- [生息環境ごとのモブ制限](#mob-limits-per-habitat)
- 必要なブロック、植物、モブ（バリアントを含む）、ブロック変換

ブロックは、検索可能なリストから選ぶか、インベントリ内のアイテムをクリックして選べます。

保存すると：

- まずレシピがチェックされます。
- `biomes.yml` が `backups/` にバックアップされます。バックアップは最新の 10 個が保持されます。
- 変更したレシピだけが書き換えられ、コメントは保持されます。
- グリーンハウスは再起動なしで、すぐに新しいルールを使用します。

各管理者の未保存の変更は、保存するか破棄するまで保持されます。編集中に別の管理者が同じレシピを保存した場合は、相手のバージョンを上書きするか、相手のバージョンから編集をやり直すかを選べます。レシピを削除してもグリーンハウスは削除されません。そのレシピを使っていたグリーンハウスは、代わりに未読み込みとして一覧に表示されます。

### テストグリーンハウスビルダー { #test-greenhouse-builder }

*Greenhouses 1.11.0 で追加されました。*

`/bsbadmin greenhouses build <recipe> [x y z] [WxDxH] [keep|clear]`（権限 `[gamemode].greenhouses.admin.build`）は、レシピに合った実際に機能するグリーンハウスを建設して登録します：

- ガラスの壁
- 自分が向いている側に、バイオームに合ったスタイルのドア
- 骨粉を入れた屋根のホッパー
- レシピに必要なブロック、水、溶岩（海洋のグリーンハウスは水で満たされ、ネザーのグリーンハウスには溶岩が置かれます）

`keep` を指定すると、木など既にあるものの周りに建設します。`clear` を指定すると、確認のあとでまず空間を空にします。`~ ~ ~` 形式の座標も使えます。

## モブスポーンのカスタマイズ（例：ウィザースケルトン）

グリーンハウスがスポーンできるすべてのモブは、レシピごとに `plugins/BentoBox/addons/Greenhouses/biomes.yml` で定義されるため、新しいモブを追加するのは設定編集だけです。レシピの `mobs:` セクションの各エントリは以下のフォーマットです：

```
ENTITY_TYPE: chance:BLOCK_TO_SPAWN_ON
```

例えば、ネザーグリーンハウスにウィザースケルトンが出現する可能性を追加するには、`NETHER:` レシピを見つけて、その `mobs:` セクションに 1 行追加してください：

```yaml
NETHER:
  # ...
  mobs:
    ZOMBIFIED_PIGLIN: 10:NETHERRACK
    PIGLIN: 10:NETHERRACK
    STRIDER: 10:LAVA
    ENDERMAN: 5:NETHERRACK
    WITHER_SKELETON: 5:NETHERRACK
```

これにより、ウィザースケルトンがグリーンハウス内のネザーラック ブロックに出現する可能性が 5% になります。スポーン先ブロックはグリーンハウス内の任意のブロックになります — より要塞のような雰囲気にするために、代わりに `WITHER_SKELETON: 10:NETHER_BRICKS` を使用することもできますが、その場合、グリーンハウス内にネザーレンガがあるとスポーンが起こります。

**/bsbadmin greenhouses reload** （または `**/acid greenhouses reload**` など、ゲームモードの管理者相当）を使用して変更を適用するか、サーバーを再起動してください。既存のグリーンハウスは再構築なしで新しいモブを取得します。

留意すべきことは：

* **1 つのレシピのすべてのチャンスは 100 以下である必要があります。** 新しいエントリが合計を 100 を超える場合、そのモブはスキップされ、エラーがログに記録されます（`Mob chances add up to > 100% in NETHER biome recipe! Skipping ...`）。1.11.0 より前は、丸め誤差のために合計がちょうど 100 のチャンスが拒否されることがありました。
* スポーンはレシピの `moblimit` と `maxmobs` の値およびモブティック間隔（`config.yml`）によっても制限されます — したがって、低いパーセンテージは実際には稀に感じることがあります。
* `ENTITY_TYPE` は有効な [Bukkit EntityType](https://jd.papermc.io/paper/1.21.5/org/bukkit/entity/EntityType.html) 名である必要があります；不明な名前はスキップされ、警告が出力されます。
* Minecraft 26.x ではムーシュルームは `MUSHROOM_COW` ではなく `MOOSHROOM` です。`biomes.yml` にある `MUSHROOM_COW` のエントリはすべて名前を変更してください。
* 1.11.0 以降は、同じ変更を[レシピエディター](#in-game-recipe-editor)を使ってゲーム内で行えます。

### 生息環境ごとのモブ制限 { #mob-limits-per-habitat }

*Greenhouses 1.11.0 で追加されました。*

`moblimit` は 1 体のモブに必要な床ブロックの数ですが、深い海、溶岩湖、飛行するモブには適さない基準です。レシピでは、`biomes.yml` にさらに 3 つの任意のキーを設定できます。各キーはそれぞれ別のモブを数え、値はモブ 1 体あたりのブロック数です：

| キー | 数えるモブ | 基準となる空間 |
|---|---|---|
| `moblimit-water` | 水の上にスポーンするモブ | 水ブロック |
| `moblimit-lava` | 溶岩の上にスポーンするモブ | 溶岩ブロック |
| `moblimit-air` | 飛行するモブ：アレイ、コウモリ、ミツバチ、ガスト、オウム、ファントム、ヴェックス | グリーンハウスの内部の体積 |

地上のモブは引き続き `moblimit` を使用し、`maxmobs` は引き続き合計の上限になります。制限が指定されていない場合、そのモブは地上のモブと `moblimit` を共有するため、新しいキーの無いレシピはこれまでどおりに動作します。同梱の `biomes.yml` では次のように設定されています：

- `moblimit-water`：砂浜、雪の砂浜、海洋（9）、川（1）
- `moblimit-lava`：ネザーと歪んだ森（9）
- `moblimit-air`：ジャングルと鍾乳洞（27）、ソウルサンドの谷（64）

1.11.0 以降、`moblimit` は正確に計算されます。81 ブロックでモブ 1 体あたり 9 ブロックなら、10 体ではなく 9 体になります。また 1.11.0 以降はグリーンハウス内での自然な（バニラの）スポーンもキャンセルされるため、レシピで指定したモブだけが現れます。

## 権限 { #permissions }

権限の完全なリストは[こちら](Permissions)にあります。

特定のバイオームを使用する権限は biomes.yml で追加できます。

例えば、ネザーバイオームの権限は **greenhouses.biome.nether** であり、ここで設定されています:

 NETHER:

    permission: greenhouses.biome.nether

権限はランク権限 **myserver.VIP** など、任意のものを設定できます。

### 一般権限:

  greenhouses.player:

     description: プレイヤーコマンドへのアクセスを付与します
     default: true

  greenhouses.admin:

     description: 管理者コマンドへのアクセスを付与します
     default: op

1.10.0 以降は、各管理者サブコマンドにも個別のノード — `greenhouses.admin.list`、`.info`、`.delete`、`.tp`、`.verify`、`.reload` — があり、いずれもデフォルトは `op` です。1.11.0 では `.edit` と `.build` が追加されました。オペレーターは何もする必要はありませんが、権限管理プラグインで管理者アクセスを付与している場合はこれらを追加する必要があります。このリリースより前は `addon.yml` にこれらが完全に欠けており、そのため op によるアクセス以外は機能しませんでした。

!!! warning "v1.11.0 の新機能 — 管理者ハブとレシピエディター、BentoBox 3.24.0 が必要"
    **リリース日:** 2026-11-22

    互換性：BentoBox API 3.24.0 以降 · Paper 1.21.11 ～ 26.3 · Java 25。

    - 🔡 **管理者ハブ。** `/[admin_command] greenhouses` で、すべての管理者ツールを使える GUI が開くようになりました。レシピの編集、グリーンハウスの閲覧、テストグリーンハウスの建設、全グリーンハウスのチェック、リロードができます。[管理者ハブ](#admin-hub)を参照してください。
    - 🔡 **ゲーム内レシピエディター。** `/[admin_command] greenhouses edit [recipe]` で、`biomes.yml` を編集したりサーバーを再起動したりせずに、バイオームレシピの作成、編集、複製、削除ができます。[ゲーム内レシピエディター](#in-game-recipe-editor)を参照してください。
    - 🔡 **テストグリーンハウスビルダー。** `/[admin_command] greenhouses build <recipe>` で、任意のレシピの実際に機能するグリーンハウスを自分が立っている場所に建設します。[テストグリーンハウスビルダー](#test-greenhouse-builder)を参照してください。
    - ⚙️ **モブのスポーンとブロック変換がなめらかに。** これまではどちらも 1 ティックですべてのグリーンハウスのすべてのブロックをスキャンしていたため、グリーンハウスが一気にモブの上限まで埋まっていました。現在は `sample-ticks` ティックごと（新しい設定、デフォルト `20`）に、ランダムに選んだ場所に対して実行されます。平均の頻度は変わりません。また、モブはワールド全体ではなく、各グリーンハウス自身の範囲内で数えられるようになりました。
    - **水、溶岩、空中で別々のモブ制限。** 新しい任意のレシピキー `moblimit-water`、`moblimit-lava`、`moblimit-air` が追加されました。[生息環境ごとのモブ制限](#mob-limits-per-habitat)を参照してください。
    - 🐛 **グリーンハウス内の自然スポーンをブロックするようになりました。** スポーンのガードが壁と屋根のブロックにしか一致していなかったため、タイガのグリーンハウスはオオカミで、ネザーのグリーンハウスはガスト、マグマキューブ、ゾンビピグリンでいっぱいになっていました。
    - 🐛 `moblimit` がモブを 1 体多く許可していた問題を修正しました。植物は生存できる場所にだけ置かれるようになりました。合計がちょうど 100% のチャンスが拒否されなくなりました。
    - 🔡 レシピパネルに**レシピの説明と MiniMessage の色**が表示されるようになり、全 22 言語に翻訳されています。
    - 新しい権限 `[gamemode].greenhouses.admin.edit` と `[gamemode].greenhouses.admin.build` が追加されました。どちらもデフォルトは `op` です。

    🔺 **BentoBox 3.24.0 と Paper 1.21.11 以降が必要です。** レシピエディターと管理者ハブは BentoBox の新しいダイアログ API とページ付きパネル API を使用するため、古いバージョンの BentoBox ではこのアドオンは読み込まれません。先に BentoBox を更新してください。

    🔺 **`biomes.yml` は置き換えられません。** 同梱のファイルは変更されています。レシピに説明と MiniMessage の名前が付き、生息環境ごとのモブ制限が設定され、`MUSHROOM_COW` は `MOOSHROOM` になりました。既存のファイルはそのまま保持されます。新しいデフォルトを使うには、変更を自分でマージするか、ファイルの名前を変更して新しいファイルを生成させてください。どちらの場合も、`MUSHROOM_COW` のエントリはすべて `MOOSHROOM` に名前を変更してください。古い名前は 26.x では無効です。

    🔡 **ロケールファイル。** すべてのテキスト修正を反映するには、サーバーを起動する前に `plugins/BentoBox/locales/Greenhouses/` を削除してください。BentoBox は既存のファイルに新しいロケールキーを追加しますが、変更されたキーは更新しません。

    [Release v1.11.0](https://github.com/BentoBoxWorld/Greenhouses/releases/tag/1.11.0)

??? warning "v1.10.2 の新機能 — Paper 26.2 でのクラッシュ修正"
    **リリース日:** 2026-09-06

    互換性：BentoBox API 2.7.1 · Minecraft 1.21.5+ · Java 21。設定またはロケール変更なし。

    - 🐛 **ホッパーが骨粉を使い尽くしたときに植物の成長がクラッシュしなくなりました。** ルーフホッパーが単一の骨粉を保持していて、少なくとも 1 つの植物が成長すると、Greenhouses は残りをゼロ量アイテムとして戻しました。古いサーバーはそれを黙って許容していました；Paper 26.2 は `EcoSystemManager.setBoneMeal` から `IllegalArgumentException: amount must be greater than 0` をスロー、毎ティック植物がエラーをログにしてクラッシュし、そのグリーンハウスの成長パスを中止します。最後の骨粉は単に削除されるようになりました。

    🔺 **Paper 26.2 以降を使用している場合、このアップデートを強くお勧めします。** ホッパーが空になるすべてのグリーンハウスは、それ以外はこのエラーを毎ティックログし、骨粉が再び追加されるまで植物の成長を停止します。

    [Release v1.10.2](https://github.com/BentoBoxWorld/Greenhouses/releases/tag/1.10.2)

??? warning "v1.10.1 の新機能 — Limits を実行している場合はリカウント"
    **リリース日:** 2026-09-01

    互換性：BentoBox API 2.7.1 · Minecraft 1.21.5+ · Java 21。設定またはロケール変更なし。

    - 🐛 **Greenhouses はモブを Limits アドオンの制限を超えて滑らせなくなりました。** Limits がエンティティ制限でスポーンをキャンセルすると、Greenhouses はスポーンされたことのないエンティティで操作を続け、「このモブはガラスの内側に適合していますか？」チェック（Ghasts は 4×4×4 で、しばしば適合しません）を実行し、それが適合しなかった場合、`remove()` を呼び出しました。Paper は、モブが世界に入ったことはないのに `EntityRemoveEvent` を発火、Limits はそれを実際の削除としてカウントし、その結果、それのカウンターが下がり、次のスポーンが通りました — 報告されたケースは 4/3 Ghasts でした。キャンセルされたスポーンは完全に放置されるようになりました。Limits 1.30.1 には、そのサイド上の一致する補強が含まれます。

    🔺 **これが見られた場合、** 影響を受けたアイランドの Limits カウンターはリビルドされるまで間違っています。プレイヤーにアップデート後に 1 回 `/[player_command] limits recount` を実行させるか（または管理者 `/[admin_command] limits calc <player>` を実行してください）。

    [Release v1.10.1](https://github.com/BentoBoxWorld/Greenhouses/releases/tag/1.10.1)

??? note "v1.10.0 の新機能 — 管理者コマンド"
    **リリース日:** 2026-07-26

    Greenhouses にようやく管理者コマンドツリーが加わりました。互換性: BentoBox API 2.7.1 · Minecraft 1.21.5+ · Java 21。

    - 🛠️ **管理者コマンド。** `list`、`info`、`delete`、`tp`、`verify`、`reload` が、ゲームモードの管理者コマンド（例: `/bsbadmin greenhouses`）の配下に登録されました。上記の「管理者コマンド」セクションを参照してください。読み込めないグリーンハウスのレコード — 重複、不明なレシピ、ワールドの欠落、位置なし — は、黙って破棄されるのではなく理由とともにメモリ上に保持されるようになり、これにより表示や削除が可能になりました。レコードが自動的に削除されることは、これまでどおりありません。
    - ⚙️ **新しい権限。** 6 つのサブコマンドにはそれぞれ `greenhouses.admin.*` 配下の独自のノードがあり、いずれもデフォルトは `op` です。このリリースより前は `addon.yml` にこれらが完全に欠けており、そのため op によるアクセス以外は機能しませんでした。
    - 🐛 **レシピが存在しなくなったグリーンハウスをチェックしても NPE が発生しなくなりました。** データベースのレコードが `biomes.yml` にないレシピを指している場合、チェックは `FAIL_UNKNOWN_RECIPE` を報告するようになりました。
    - 🐛 **位置を持たないレコードで `getFloorHeight` が例外を投げなくなりました** — 最も壊れている可能性が高いのは、まさにそうしたレコードです。バウンディングボックスにフォールバックします。
    - 🔺 **雪の処理が、走査したすべての列からの成功を報告するようになりました。** 最後の列だけではありません。`SnowTracker` は列ごとに結果を上書きしていたため、90 の列で雪を作りながら最後の 1 列で失敗したグリーンハウスは失敗と報告されていました — この値はホッパーから水を消費するかどうかを決めるものです。
    - 🧹 SonarCloud の未解決の 68 件の問題をすべて解消し、5 つのメソッドを認知的複雑度のしきい値以下にリファクタリング、デッドコードを削除し、テストスイートを 177 件から 224 件に増やしました。

    🔡 **翻訳者を募集しています。** 管理者コマンドにより `greenhouses.commands.admin.*` 配下にメッセージが追加されましたが、現在は英語のみです。他の 24 個のロケールファイルは、翻訳されるまでキー名にフォールバックします。

    🔺 **3 つのプレイヤーコマンドが削除されましたが、いずれも動作していませんでした。** `InfoCommand`、`ListCommand`、`RecipeCommand` は、中身がプレースホルダーの未登録スタブでした。`InfoCommand` に至っては自身を `make` というラベルで宣言しており、もし誰かが有効にしていたら本物の make コマンドと衝突していたはずです。このページでは以前 `greenhouses list` と `greenhouses recipe` を動作するプレイヤーコマンドとして掲載していましたが、それは誤りであり、修正しました。引数なしの `/is greenhouses` は引き続きレシピ GUI を開きます。

    [Release v1.10.0](https://github.com/BentoBoxWorld/Greenhouses/releases/tag/1.10.0)

??? warning "v1.9.6 の新機能 — 重なり合ったグリーンハウスを診断できるように"
    **リリース日:** 2026-07-25

    - 🐛 **重なり合ったグリーンハウスを診断できるようになりました。** 保存されている 2 つのグリーンハウスが重なっている場合、起動時に一方がスキップされますが、以前のログ行は `Greenhouse overlaps with another greenhouse. Skipping...` としか出力せず、対処の手掛かりが何もないまま再起動のたびに繰り返されていました。警告は**両方**のレコードについて `uniqueId`、レシピ、オーナー、ワールド、位置、バウンディングボックスを示し、修正方法も伝えるようになりました。要約行は `Loaded 63 greenhouses out of 65 in the database.` のように表示され、末尾にスキップされた件数の集計が付きます。
    - 🔺 **グリーンハウスの読み込み順序が決定的になりました。** グリーンハウスはデータベースが返した順に読み込まれていたため、重なり合う 2 つのレコードのどちらが残るかは不定で、再起動のたびに入れ替わることもありました。読み込み前に `uniqueId` でソートされるようになったので、どちらかのレコードを削除するまで結果は安定します。
    - ⚙️ **`biomes.yml` の `OCEAN` レシピから重複した `SQUID` エントリを削除しました。** 2 回記載されていたため、新しいバージョンのサーバーでは SnakeYAML が重複キーの警告を出していました。YAML は最後の出現を採用するので、実効値（`20:WATER`）は保たれており、モブのスポーンに変更はありません。

    ⚙️ **`biomes.yml` の修正は自動的には適用されません。** サーバーにはすでに独自の `biomes.yml` がディスク上にあり、アドオンはそれを上書きしません。`SQUID` に関する SnakeYAML の重複キー警告が出る場合は、`plugins/BentoBox/addons/Greenhouses/biomes.yml` を開いて `OCEAN` セクションを探し、2 つある `SQUID:` 行のうち最初の 1 行を削除してください。新規インストールでは修正済みのファイルが自動的に配置されます。

    🔺 **このリリースは重なり合ったグリーンハウスを報告しますが、削除はしません。** スキップされたレコードは意図的にデータベースに残されます — プレイヤーのグリーンハウスを黙って削除するのは、警告が繰り返し出続けるより悪いことだからです。1.9.6 では、ログに出力されるようになった `uniqueId` を使って古いレコードを自分で削除する必要がありました。1.10.0 では、それをゲーム内で行える管理者コマンドが追加されています。

    [Release v1.9.6](https://github.com/BentoBoxWorld/Greenhouses/releases/tag/1.9.6)

??? note "v1.9.5 の新機能"

    植物の成長とレシピ GUI に焦点を当てたバグ修正リリースです。詳細は [Release v1.9.5](https://github.com/BentoBoxWorld/Greenhouses/releases/tag/1.9.5) をご覧ください。
