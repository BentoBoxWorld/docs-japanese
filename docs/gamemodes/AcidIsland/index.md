# AcidIsland

**AcidIsland** は、酸の海に囲まれた島でプレイヤーが生き残りを賭けるゲームモードです。

作成・メンテナンス: [tastybento](https://github.com/tastybento)

{{ addon_description("AcidIsland") }}

## ストーリー
酸の海に浮かぶ小さな島から始まりましょう！スカイブロックが好きなら、新たな挑戦としてAcidIslandがぴったりです。

スカイブロックの変種ですが、虚空の代わりに危険な酸の海があなたを待っています。落ちれば只では済みません。また、ボートで他のプレイヤーの島に渡ることもできます。

## インストール

0. BentoBoxをインストールし、データフォルダを生成するためサーバーを少なくとも1回起動します。
1. このjarファイルをBentoBoxプラグインのaddonsフォルダに配置します。
2. サーバーを再起動します。
3. アドオンがワールドとデータフォルダを作成し、フォルダ内にconfig.ymlが生成されます。
4. サーバーを停止します。
5. config.ymlを希望通りに編集します。
6. ワールドの生成に関わる設定を変更した場合は、初回起動で作成されたワールドフォルダを削除します。
7. サーバーを再起動します。

### 浄化された水

!!! new "AcidIsland 1.22.0で追加"
    酸の海は相変わらず危険ですが、ついに水を**浄化**できるようになりました。酸の水入り瓶を飲むとバニラの毒エフェクトがかかり、浄化された水入り瓶を飲むと体力が回復します。どのアイテムが安全かひと目で分かるよう、水アイテムには色付きの説明文が付きます。水を浄化する方法は4通り ― かまどで水入り瓶や水バケツを精錬する、醸造台で水入り瓶を石炭と組み合わせる、鍾乳石の滴を大釜に集める ― のどれでもお好みで。

??? note "acid.purified-water.enabled"
    浄化された水の機能全体のマスタースイッチです。`false` にすると、タグ付け、かまど/醸造の介入、大釜の追跡がすべて停止します。

    デフォルト: `true`

??? note "acid.purified-water.heal-amount"
    浄化された水入り瓶を飲んだときに回復するハートの半分単位の量です。`4.0` はハート2個分になります。

    デフォルト: `4.0`

??? note "acid.purified-water.bucket-furnace-enabled"
    かまどで水バケツを精錬して浄化された水バケツを作ることを許可します。精錬時間は100秒（瓶の5倍）です。サーバーのバランス上「簡単すぎる」と感じる場合は `false` に設定してください。

    デフォルト: `true`

??? note "acid.purified-water.nether-enabled"
    このアドオンのネザーワールド（島型・バニラ型どちらも）で浄化された水の仕組みを有効にします。

    デフォルト: `true`

??? note "acid.purified-water.end-enabled"
    このアドオンのエンドワールド（島型・バニラ型どちらも）で浄化された水の仕組みを有効にします。

    デフォルト: `true`

### 硫黄の海

!!! new "AcidIsland 2.0.0 で追加"
    Minecraft 26.2 以降では、酸の海は酸性の緑色をした硫黄水になり、あちこちで泡立つ硫黄噴出孔が水面に吐き気のガスを漂わせ、周期的に間欠泉として噴出します。海底は砂・砂利・砂岩・凝灰岩を重み付けで混ぜたものにマグマブロックが泡立ち、26.2 以降ではさらに硫黄と辰砂が散りばめられます。同じ jar は Minecraft 1.21.x のサーバーでも引き続き動作し、その場合 26.2 の機能は自動的に無効になり、水は従来の温暖な海にフォールバックします。

!!! warning "`default-biome` と `make-structures` はワールド生成の設定です"
    この2つのオプションは、チャンクが生成される時点で焼き込まれます。BentoBox はこれらをゲーム中に変更することをサポートしていません — 既存のチャンクは現在の見た目のままなので、新しいワールドで始めない限り、古いチャンクの境界で見た目の継ぎ目が生じることを想定してください。`sulfur-vent-chance` は例外で、2.1.0 以降は稼働中のサーバーでも変更できます。単に、変更後に新しく生成されるチャンクにのみ反映されるというだけです。

??? note "world.default-biome"
    オーバーワールドのデフォルトバイオームです。`SULFUR_CAVES`（Minecraft 26.2 以降）にすると、酸性の緑色をした水とそれに合った緑色の霧になります。それより古いサーバーではこのバイオームが存在しないため、代わりに `WARM_OCEAN` が使用されます。

    デフォルト: `SULFUR_CAVES`（2.0.0 より前は `WARM_OCEAN`）

??? note "world.sulfur-vent-chance"
    海面のすぐ下に硫黄噴出孔が生成される、チャンクあたりの確率（0～100）です。噴出孔は濃硫黄をマグマブロックの上に重ねた構造で、泡立ち、ガスを出し、間欠泉として噴出します。形状は煙突型・マウンド型・双子型・とがった岩塊型の4種類の自然な形があり、ランダムに変化します。Minecraft 26.2 以降が必要で、それより古いサーバーでは無視されます。

    2.1.0 以降、この設定はワールドをリセットせずに変更できます。新しい値は、変更後に新しく生成されるチャンクにのみ適用されます。

    デフォルト: `10`

??? note "world.make-structures"
    ワールドにバニラの構造物を生成します。トライアルチャンバーなどの地下構造物は海底の下に埋まった状態で生成されるため、プレイヤーが地下を掘り進める理由になり、スターターキットのトライアルキーを実際に使えるようになります。

    デフォルト: `true`（2.0.0 より前は `false`）

### 間欠泉への供物

!!! new "AcidIsland 2.1.0 で追加、2.1.1 で完成"
    硫黄噴出孔の周りの水にアイテムを投げ入れると、間欠泉がそれを供物として飲み込みます。噴出孔が次に噴出するとき、水柱から報酬が吐き出されます — そのまま返されるのではなく、変成された形で返ってきます。何を与えるかによって、何が出てくるかが決まります。鉱石を捧げれば宝石寄りに、木材を捧げれば生き物寄りになります。この仕組みには Minecraft 26.2 以降（硫黄噴出孔が存在するバージョン）が必要で、それより古いサーバーでは自動的に無効になります。

    2.1.1 以降、噴出孔は**賭けではなく取引をする**ようになりました。供物にどれだけの価値があったかを計算し、それとほぼ同等の価値の報酬を返します。ダイヤモンドは宝石として返り、丸石1スタックは丸石相応のがらくたとして返ります。噴出孔の近くを漂うアイテムはその水たまりへ引き寄せられるため、投げる場所が正確である必要はありません。また、供物を与えられた噴出孔は数秒後に噴出するよう促されるので、プレイヤーがまだ見ている間に報酬が届きます。

    カウントされるのはプレイヤーが投げたアイテムだけです — 死亡時のドロップ、ブロックのドロップ、水たまりに流れ込んだモブのドロップは対象外です。噴出孔の水たまりの中で酸に溶かされたアイテムは、失われるのではなく供物としてカウントされます。また、吐き出された報酬にはマークが付いているため、新たな供物として再利用されることは決してありません。噴出孔を採掘してしまうと、保留中の供物は失われます。

??? note "world.geyser-offerings.enabled"
    間欠泉への供物機能のマスタースイッチです。

    デフォルト: `true`

??? note "world.geyser-offerings.max-rewards"
    1回の噴出で吐き出される報酬の最大数です。供物として与えられたアイテム数にかかわらず、この数が上限になります。

    デフォルト: `12`

??? note "world.geyser-offerings.match-value"
    アイテム1個につきランダムな報酬を1つ返すのではなく、ほぼ同等の価値の報酬で供物に応えます。噴出孔は破壊するのではなく変成させます。ダイヤモンドを与えればダイヤモンド1個分の価値を返す義務を負い、丸石を与えれば丸石を返します。価値は `geyser-values.yml` から取得され、このファイルは Level アドオンのブロック価値にフォールバックできます。2.1.0 の「アイテム1個につき1回抽選」方式に戻したい場合は、これを無効にしてください。

    デフォルト: `true`（2.1.1 で追加）

??? note "world.geyser-offerings.exchange-rate"
    価値をそろえて返すときに、噴出孔が返す供物価値の割合です。`1.0` は等価交換、`1.0` 未満では噴出孔が手数料を取り、`1.0` を超えると供物を捧げること自体が儲かるようになります — プレイヤーは必ずこれを利用して稼ぐので、上げるときは慎重に。

    デフォルト: `1.0`（2.1.1 で追加）

??? note "world.geyser-offerings.reward-ceiling"
    報酬1つあたりの価値の上限を、その供物の中で最も価値の高いアイテムの何倍かで指定します。丸石1スタックはエメラルド1個分の価値があり、丸石製造機は無限なので、この上限がないと噴出孔は宝石の印刷機になってしまいます。`geyser-loot.yml` の `from:` リストで指定された報酬はこの上限を無視します — 管理者自身が書き記した変成は常に許可されます。`0` にすると無制限になります。

    デフォルト: `8.0`（2.1.1 で追加）

??? note "world.geyser-offerings.erupt-on-offering"
    バニラの噴出サイクルを待たずに、供物を与えられた噴出孔を数秒後に噴出するよう促します。プレイヤーがまだその場にいて見られるうちに、供物に続いて報酬が届くようになります。これを無効にすると、噴出のタイミングは完全にバニラに委ねられます — その場合、供物は噴出孔が噴出するまで保持されます。

    デフォルト: `true`（2.1.1 で追加）

#### geyser-loot.yml

報酬は `geyser-loot.yml` で定義します。このファイルは初回起動時に `plugins/BentoBox/addons/AcidIsland/` へコピーされます。各エントリはアイテムか、コンソールコマンドのいずれかです。

```yaml
loot:
  - {item: RAW_IRON, weight: 30, channel: mineral, amount: {min: 1, max: 3}}
  - {item: OBSIDIAN, weight: 10, channel: nether, from: [MAGMA_BLOCK, BASALT, LAVA_BUCKET]}
  - {item: MUSIC_DISC_13, weight: 1, from: [BONE, GUNPOWDER]}
  - {command: "give %player% cod 1", weight: 1, value: 4}
```

| キー | 意味 |
| --- | --- |
| `item` / `command` | 報酬の内容です。コマンドはコンソールから実行され、`%player%` はプレイヤー名に置換されます。 |
| `weight` | そのエントリが抽選される相対的な確率です — 値が大きいほどよく出ます。 |
| `channel` | 任意。`gems`、`nether`、`mineral`、`forestry`、`husbandry` のいずれかです。供物は、その供物の*価値*のうち各チャンネルに振り分けられた割合に応じて、抽選テーブルを自分のチャンネル寄りに引き寄せます。 |
| `from` | 任意。その報酬へ変成する素材のリストです。いずれかを供物として捧げると、このエントリが抽選される確率は8倍になります — さらに `reward-ceiling` を無視するため、投入したものよりはるかに価値の高いものを噴出孔が返す唯一の手段になります。 |
| `amount` | 任意のアイテム個数です。固定値でも `{min, max}` の範囲でも指定できます。デフォルトは `1` です。 |
| `value` | 任意。その報酬1個の価値を指定し、素材本来の価値を上書きします。コマンド報酬はこれを設定しない限り価値ゼロとして扱われるため、有料級のコマンドには必ず価値を設定してください。さもないと毎回の支払いに登場してしまいます。 |

!!! warning "2.1.0 からのアップグレード"
    `geyser-loot.yml` は存在しないときにのみ書き出されます。そのため 2.1.0 から残っているファイルには `from:` の変成も `value:` フィールドも追加されず、名前付き変成はいずれも機能しません。ファイルを削除して再生成させたうえで、ご自身の変更を改めて適用してください。

#### geyser-values.yml

`geyser-values.yml` は、各素材が噴出孔にとってどれだけの価値を持つかを定めます。この尺度は任意のもので — 意味を持つのは比率だけです — 鉄インゴット `6`、金インゴット `12`、エメラルド `15`、ダイヤモンド `45` を基準にしています。したがってダイヤモンド1個はエメラルド3個、あるいはエメラルド1個と金インゴット2個として返ってきます。

価値は次の順序で解決され、最初に見つかったものが採用されます。

1. ファイル内の `values:` マップ
2. Level アドオンがインストールされていて `use-level-addon: true` の場合は、そのワールドにおける **Level アドオン**のブロック価値 — すでに Level を調整済みのサーバーは、同じ調整を二度行う必要がありません。`values:` からエントリを削除すると、その素材は Level に委ねられます。
3. `default:` の価値。他のどこにも情報がない素材に使われます。

価値は素材のみで決まります。エンチャント、カスタム名、シュルカーボックスの中身は考慮されないため、装備品はその基礎素材の価値になります。

このファイルは初回起動時に自動で作成されます。

## API

他のアドオンは、いずれも 2.1.0 で追加された次の2つのイベントを使って、間欠泉への供物の仕組みに介入できます。

- `GeyserSacrificeEvent` — 噴出孔が供物を飲み込んだときに発火します。キャンセル可能です。
- `GeyserTransmuteEvent` — 噴出孔が報酬を吐き出したときに発火します。

## 変更履歴

!!! warning "v2.1.1の新機能 — 噴出孔は賭けではなく取引をする（`geyser-loot.yml` の削除が必要）"
    **リリース日:** 2026-07-26

    2.1.0 では間欠泉への供物の仕組みは出荷されましたが、本来それに伴うはずだった経済は伴っていませんでした。噴出孔は投げ込まれたアイテム1個につき報酬を1回抽選するだけだったので、丸石1スタックとダイヤモンド1個が同じ1回の抽選しか買えず、しかもこの仕組みはプレイヤーに一言も語りかけませんでした。2.1.1 でこれが完成します。互換性: BentoBox API 3.14.0 · Minecraft 1.21.5 – 26.2（間欠泉関連の機能には 26.2 以降が必要）· Java 21。

    - ⚙️ 🔺 **価値のマッチング。** 新しい `geyser-values.yml` が、各素材が噴出孔にとってどれだけの価値を持つかを定めます。鉄インゴット 6、金インゴット 12、エメラルド 15、ダイヤモンド 45 が基準です。噴出孔は与えられたものの価値を合計し、その価値を使い切るまで、まだ支払える報酬を抽選し続けます。`world.geyser-offerings` の下に4つのオプションが追加されました: `match-value`、`exchange-rate`、`reward-ceiling`、`erupt-on-offering`（上記の「設定」を参照）。このファイルに記載のない素材については、`use-level-addon: true` によって **Level アドオン**のブロック価値にフォールバックできます。
    - ⚙️ **名前付き変成。** `geyser-loot.yml` のルートエントリが `from:` リストを受け付けるようになりました。そこに挙げた素材がその報酬へ変成します — マグマブロックは黒曜石に、鉄は金に、骨と火薬はミュージックディスクになります。`from:` を持つエントリは抽選確率が8倍になり、`reward-ceiling` を無視するため、本来ならモブトラップが必要になるような報酬を置く場所として最適です。
    - 🔡 **噴出孔がついに言葉を発します。** 新しい `acidisland.geyser` ロケールセクションに、供物・沸き立ち・支払いのメッセージと、5つの報酬チャンネルの表示名が、24言語すべてに追加されました。デフォルトではアクションバーメッセージとして表示されます — `[actionbar]` タグを外すとチャットに送信されます。
    - **投げる場所が正確である必要はなくなりました。** 噴出孔の近くを漂うアイテムはその水たまりへ引き寄せられ、供物を与えられた噴出孔は数秒後に噴出するよう促されるため、プレイヤーがまだ見ている間に支払いが届きます。
    - **チャンネルの偏りが価値基準に。** 供物は引き続き報酬テーブルを自分のチャンネル寄りに引き寄せますが、その引き寄せる力はアイテム数ではなく価値で重み付けされるようになりました — ダイヤモンド1個は、それと同じ価値の丸石1スタックと同じだけ強く方向づけます。

    🔺 2.1.0 を使用していた場合は、`plugins/BentoBox/addons/AcidIsland/` から **`geyser-loot.yml` を削除してください。** このファイルは存在しないときにのみ書き出されるため、既存のファイルには `from:` の変成も `value:` フィールドも追加されません。再生成されたファイルに、ご自身の変更を改めて適用してください。

    ⚙️ `geyser-values.yml` は初回起動時に自動で作成され、4つの新しいオプションは起動時に `config.yml` へ追加されます。既存の設定はそのまま保持されます。🔡 `acidisland.geyser` の文字列を取り込むため、ロケールファイルを再生成または更新してください。2.1.0 の支払い方式のほうがよいサーバーは、`match-value: false` に設定すれば、それ以外はすべてそのまま利用できます。

??? note "v2.1.0の新機能 — 間欠泉への供物"
    **リリース日:** 2026-07-26

    AcidIsland 2.1.0 は、硫黄噴出孔を単なる背景から経済の仕組みへと変えます。噴出孔の周りの水にアイテムを投げ入れると、間欠泉がそれを供物として飲み込み、次の噴出のときに変成された報酬を水柱から吐き出して報いてくれます。互換性: BentoBox API 3.14.0 · Minecraft 1.21.11 – 26.2（間欠泉への供物には 26.2 以降が必要）· Java 21。

    - ⚙️ **間欠泉への供物。** 硫黄噴出孔の周りの水たまりに漂うアイテムが、ジュッという音とともに供物として飲み込まれます — 水たまりの範囲内であればどこでもよく、ピクセル単位の精密さは不要です。噴出孔が次に噴出するとき、供物として捧げたアイテム1個につき報酬1つ（上限あり、設定可能）が、放射状の噴水のように水柱から吐き出されます。
    - **チャンネル。** 供物は **gems**、**nether**、**mineral**、**forestry**、**husbandry** のチャンネルに分類され、報酬テーブルを捧げたものの方向へ偏らせます。
    - ⚙️ **新しい `geyser-loot.yml`** が初回起動時にアドオンのデータフォルダへコピーされます。個数の範囲を指定できる重み付きのアイテムエントリに加え、`%player%` の置換に対応したコンソールコマンド報酬を定義できます。
    - ⚙️ **新しい `world.geyser-offerings` 設定セクション**: `enabled`（デフォルト `true`）と、噴出1回あたりの `max-rewards`（デフォルト `12`）。
    - **他のアドオン向けの新しい API イベント**: `GeyserSacrificeEvent`（キャンセル可能）と `GeyserTransmuteEvent`。
    - **酸によるアイテム破壊と併用できます。** 噴出孔の水たまりの中で酸に溶かされたアイテムは、`acid.damage.acid.item` の破壊時間の設定にかかわらず、失われるのではなく供物としてカウントされます — また、吐き出された報酬にはマークが付いているため、新たな供物として再利用されることは決してありません。採掘された噴出孔は保留中の供物を失います。間欠泉は保管庫ではありません。
    - ⚙️ **`world.sulfur-vent-chance` の変更にワールドのリセットが不要になりました。** 新しく生成されるチャンクにのみ影響するため、管理者は稼働中のサーバーで噴出孔の密度を調整できます。

    **ワールドのリセットは不要です。** 供物は既存のどの硫黄噴出孔でも機能します — このリリースにワールド生成の変更は含まれていません。

!!! warning "v2.0.0の新機能 — 硫黄の海（ワールド生成の変更）"
    **リリース日:** 2026-07-20

    AcidIsland は Minecraft 26.2 の硫黄プールを、酸の海を象徴する見た目として取り入れます。互換性: BentoBox API 3.14.0 · Minecraft 1.21.11 – 26.2（硫黄関連の機能には 26.2 以降が必要）· Java 21。

    - ⚙️ **酸性の緑色をした硫黄水。** オーバーワールドのデフォルトバイオームが `SULFUR_CAVES` になり、すべての水が酸性の緑色に、霧もそれに合った緑色になります。26.2 より古いサーバーではこのバイオームが存在しないため、ワールドは `WARM_OCEAN` にフォールバックします。
    - ⚙️ **硫黄噴出孔と間欠泉。** 海面のすぐ下に濃硫黄の噴出孔が生成されます。泡が立ち、水面には吐き気のガス雲が漂い、周期的に間欠泉が噴出します。形状は4種類の自然な形があり、ランダムに変化します。チャンクあたりの確率は新しい `world.sulfur-vent-chance` オプション（デフォルト 10%）で設定します。Minecraft 26.2 以降が必要です。
    - **変化に富んだ海底。** これまで殺風景な砂だけだった海底が、砂・砂利・砂岩・凝灰岩を重み付けで混ぜたものになり、マグマブロックが泡立ち、26.2 以降ではさらに硫黄と辰砂が加わります。それより古いサーバーでは、26.2 のブロックの代わりに砂利と凝灰岩が使われます。
    - **新しいスターター島「Sulfur Spring Refuge」。** 逞しいトウヒの露頭に落ち葉、アイブロッサム、ウィザーローズ、ポドゾル、その下に凝灰岩の聖域、そしてヤギが1匹。スターターキットは桜の林の島と同じ実用的な内容です。すべて 1.21 で安全に使えるブロックだけで作られています。
    - ⚙️ **構造物がデフォルトで有効に。** `world.make-structures` のデフォルトが `true` になり、トライアルチャンバーなどの地下構造物が海底の下に埋まった状態で生成されます。

    🔺 **ワールド生成の変更です。** 新しい水のバイオーム、噴出孔、海底、構造物はすべてチャンク生成時に焼き込まれます。既存のワールドでは、探索済みのチャンクは現在の見た目のままです。2.0.0 を完全に体験するには新しいワールドで始めるか、古いチャンクの境界で見た目の継ぎ目が生じることを想定してください。

    ⚙️ **既存の設定は変更されません。** お使いの `config.yml` は保存されている値をそのまま保持します。既存の環境で新しいデフォルトを採用するには、`default-biome: SULFUR_CAVES` と `make-structures: true` を設定し、`sulfur-vent-chance: 10` を追加するか、設定ファイルを削除して再生成してください。

    🔺 **既存環境での新しいブループリント。** BentoBox は同梱のブループリントを、ブループリントフォルダが*存在しない*場合にのみ展開します。既存の環境で新しい島の選択肢を表示するには、`sulfur-spring.blueprint` と `sulfur_spring.json` を jar から `plugins/BentoBox/addons/AcidIsland/blueprints/` にコピーしてください。

??? note "v1.22.0の新機能 — 浄化された水の仕組み"
    **リリース日:** 2026-04-15

    酸の水を浄化して、安全に飲んだり、農業に使ったり、瓶詰めにして持ち歩けるようになりました。すべての水アイテムには <span style="color:red">Acid Water</span> または <span style="color:green">Purified Water</span> の色付きの説明文が付き、大釜はサーバー再起動をまたいで中の水の状態を覚えています。

    - ⚙️ **浄化された水を追加** — 浄化方法は4通り。かまどで水入り瓶を精錬する（10秒）、醸造台で水入り瓶と石炭を組み合わせる、かまどで水バケツを精錬する（100秒、オン/オフ切替可能）、または鍾乳石の滴を大釜に集める。
    - ⚙️ **飲用時の効果** — 酸の水入り瓶はバニラの毒エフェクトを付与し、浄化された水入り瓶は体力を回復します（回復量は `acid.purified-water.heal-amount` で調整可能）。
    - ⚙️ 新しい設定ブロック `acid.purified-water.*` を追加（詳細は上の「設定」セクションを参照）。マスタースイッチ、回復量、水バケツのかまど精錬の切替、ネザー/エンドごとの切替を含みます。
    - 🔡 `acidisland.purified-water.*` 以下の新しいロケールキーを2つ追加。18言語すべてに同期済みです。
    - **新しいイベント** — 他のプラグインからフックできるよう、`ItemFillWithAcidEvent` と `PlayerDrinkPurifiedWaterEvent` を追加しました。
    - コード整備: パターンマッチングの `instanceof` 採用、`Math.clamp` の利用、`onPlayerMove`/`getWorld`/`findEntities`/`makeNetherRoof` の複雑度削減、テストの最新化など。
