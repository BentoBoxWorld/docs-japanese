# アイランド保護、フラグ & ランク { #island-protection-flags-ranks }

[TOC]

## はじめに { #introduction }

BentoBoxゲームワールドでプレイヤー（またはピストン、モブ、火、爆発などの環境）ができることはすべて、**フラグ**によってコントロールされています。各フラグは1つのアクションの種類をカバーします。例えばブロックを壊す、チェストを開く、動物を傷つけるなど。ほとんどのフラグはBentoBoxで提供されています。[Greenhouses](https://github.com/BentoBoxWorld/Greenhouses)などのアドオンは独自のフラグを追加できます。

[フラグのリスト](Flags.md)ですべてのフラグ、アイコン、デフォルトを参照してください。

フラグには3つのタイプがあります：

| タイプ | 制御内容 | 変更者 |
| --- | --- | --- |
| **保護フラグ** | どの[ランク](#ranks)がアクションを行えるか。例：ブロックを壊す。アイランド上ではランクです。アイランド外ではオン/オフです。 | アイランド所有者が自分のアイランドで。管理者がワールドと新規アイランド用。 |
| **設定フラグ** | アイランド全体のオン/オフスイッチ。例：PVPまたは動物スポーン。 | アイランド所有者。 |
| **ワールド設定** | ゲーム全体のスイッチ。例：クリーパーダメージ。 | 管理者のみ。 |

### アイランド上、アイランド外、新規アイランド { #on-an-island-off-an-island-and-new-islands }

最も一般的な混乱は、1つの保護フラグが**3つの異なる値**を持ちうることです。プレイヤーが立っている場所と対象のアイランドに応じて：

| 質問 | 設定場所 | パネルタブ |
| --- | --- | --- |
| このアイランド**上**でこのアクションを行えるのはどのランク？ | そのアイランドの設定 | `/[player_command] settings` → **保護フラグ** |
| このワールドの**アイランド外**のどこでも誰もができること？ | ワールドの保護フラグ（ゲームモードの`config.yml`の`world.flags`） | `/[admin_command] settings` → **ワールド保護** |
| **新規作成**されたアイランドがどのランクで開始するか？ | ゲームモードの`config.yml`の`world.default-island-flags` | `/[admin_command] settings` → **アイランドデフォルト** |

1つを変更しても他は変わりません。特に、**アイランドデフォルトはアイランド外では効果がなく**、**ワールド保護はアイランド上では効果がありません**。

### アイランドの終わり { #where-an-island-ends }

アイランドの保護はそのグリッドスクエア全体をカバーしていません。アイランドは`distance-between-islands`間隔で配置されますが、各アイランドは**保護範囲**内でのみ保護されます。これはアイランドの中心から各方向に`protection-range`ブロックの正方形です。範囲は`/[admin_command] range`またはパーミッション`[gamemode].island.range.<number>`でアイランドごとに上げることができます。

保護範囲外のどこでもが**アイランド外**としてカウントされます。アイランドのグリッドスクエア内でも。ここには、アイランド間のボイド、アイランドでないワールドスポーン周辺、Boxedなどのゲームモードの荒地を含みます。アイランド外では、[ワールド保護](#world-protections)が適用されます。

## ランク { #ranks }

各プレイヤーは各アイランドでランクを持っています：所有者、メンバー、訪問者など。保護フラグは**そのアクションを行える最低ランク**を設定します。そのランク以上のすべてのプレイヤーが許可されます。ランクは番号なので、より高いほどより信頼できます：

| ランク | 値 | 誰が持つか |
| --- | --- | --- |
| バン済み | -1 | アイランドからバンされたプレイヤー。入ることはできません。 |
| ビジター | 0 | アイランドの一部ではないプレイヤー。 |
| Coop | 200 | `/[player_command] team coop`で追加されたプレイヤー。すべてのチームメンバーがログオフしたら削除されます。 |
| 信頼 | 400 | `/[player_command] team trust`で追加されたプレイヤー。ログイン間で保持されます。 |
| メンバー | 500 | チームメンバー。 |
| サブオーナー | 900 | `/[player_command] team promote`で昇進したチームメンバー。 |
| 所有者 | 1000 | アイランド所有者。 |
| Mod | 5000 | プレイヤーに与えられません。予約済み。 |
| 管理者 | 10000 | プレイヤーに与えられません。予約済み。 |

したがって、フラグが*メンバー*に設定されている場合、メンバー、サブオーナー、所有者はアクションを実行できますが、信頼できるプレイヤー、coops、訪問者はできません。フラグが*ビジター*に設定されている場合、誰でもできます。

アドオンはこれらの間にさらにランクを登録できます。

管理者は`/[admin_command] getrank <player>`と`/[admin_command] setrank <player> <rank>`でプレイヤーのランクを確認または変更できます。

## アイランド設定パネル { #island-settings-panel }

**設定パネル**はアイランド所有者がアイランドを設定する場所です。`/[player_command] settings`で開きます（パーミッション`[gamemode].island.settings`）。アイランド上のすべてのプレイヤーは表示できます。所有者のみが変更でき、また所有者が**設定を変更**フラグ（作業台、最上段）で許可したランクも変更できます。

![設定パネルのデフォルトビュー](https://user-images.githubusercontent.com/20014332/80591492-1689c100-8a1e-11ea-9a59-c55f35ab6ad9.png)

*設定パネルのデフォルトビュー。*

パネルはプレイヤーが立っているアイランドを表示するか、他の場所にいる場合は自分のアイランドを表示します。管理者は`/[admin_command] settings <player_name>`で任意のプレイヤーのアイランドを開けます。

### 保護フラグタブ { #protection-tab }

**保護フラグ**タブが最初に表示され、アイランドの**保護フラグ**をリストします。

フラグを**左クリック**してそれが必要とするランクを上げて、**右クリック**して下げてください。ロアはランクをリストし、現在のランクをハイライトします。*所有者*を越えてラップアラウンドすると*ビジター*になり、反対もそうです。

![保護フラグの例](https://user-images.githubusercontent.com/20014332/62974085-b31c1c80-be17-11e9-8b27-2fd4bf54ae87.png)

*保護フラグの例。*

新しいアイランドは[アイランドデフォルト](#island-defaults)タブで設定されたランクで開始します。ほとんどのフラグは*メンバー*で開始するため、訪問者は見ることができますが触ることはできません。一部は低く開始して訪問者が使用できるようにします。例えば、*ロック*は*ビジター*で開始するため、アイランドは訪問者に開かれています。

![デフォルトでビジターがインタラクションできる保護フラグの例](https://user-images.githubusercontent.com/20014332/62974359-553c0480-be18-11e9-8679-0033fd8bf8bd.png)

*デフォルトでビジターがインタラクションできる保護フラグの例。*

### 設定タブ { #settings-tab }

**設定**タブはアイランドの**設定フラグ**をリストします：PVP、火の蔓延、葉の腐食、モブスポーンなどのアイランド全体のオン/オフスイッチ。設定をクリックして切り替えてください。

各設定にはまた、パーミッション`[gamemode].settings.<FLAG_ID>`（または`[gamemode].settings.*`）が必要です。これによりサーバーは設定をプレイヤーから完全に取り去ることができます。例えば、PVPをオフにするのを止めるため。PVPなどの一部の設定には変更間のクールダウンがあります。

このタブには[コマンドランク](#command-ranks)アイコンもあります。

### ワールド保護ビュー { #world-protection-view }

!!! new "BentoBox 3.22.0で追加"

    アイランドを持たず、別のアイランドエリアに立っていないプレイヤーは、読み取り専用の**ワールド保護**タブを代わりに見ます。これは管理者が[ワールド保護](#world-protections)タブで設定した通り、アイランド外で誰が何をできるかを表示します。これは情報専用で、ここから変更することはできません。

**表示モード**に応じて、設定パネルはより多くまたはより少ないフラグを表示します。モードは`BASIC`、`ADVANCED`、または`EXPERT`です。パネルの右上隅のインゴットをクリックしてモードを変更してください。

![基本保護フラグ](https://user-images.githubusercontent.com/20014332/80592424-b98f0a80-8a1f-11ea-94f5-3b2246b6ae61.png)

`ADVANCED`はより細かいコントロール用にさらにフラグを表示します。

![高度な保護フラグ](https://user-images.githubusercontent.com/20014332/80592698-24d8dc80-8a20-11ea-93d5-3b1b8dbcd18d.png)

`EXPERT`はすべてのフラグを表示し、追加ページが必要です。

![エキスパート保護フラグ](https://user-images.githubusercontent.com/20014332/80592793-4df96d00-8a20-11ea-891e-8833578642e4.png)

!!! new "BentoBox 3.23.3で変更"
    設定パネルは各プレイヤーが最後に選択した表示モードを記憶し、次に開くときそれで開きます。1つのモードが保護と設定タブで共有されます。選択されたモードで表示するフラグがなければ、プレイヤーの選択を変更することなく次のモードアップを表示します。管理者設定パネルは常に`EXPERT`で開きます。

### フラグを隠す { #hide-flags }

オペレーターはフラグをプレイヤーから隠すことができます：設定パネルを開いてフラグアイコンを++shift+left-button++です。アイコンが「消滅の呪い」グリントを取得し、プレイヤーはフラグをもう見ません。もう一度同じことをしてフラグを表示してください。隠されたフラグはゲームモードの`config.yml`の`world.hidden-flags`に保存されます。

フラグを隠すことはそれをパネルから削除するだけです。フラグは現在の値を保持し、依然として適用されます。プレイヤーがフラグを変更できないようにするには、まず値を設定してからフラグを隠してください。

![デフォルトフラグ](https://user-images.githubusercontent.com/20014332/80591609-45a03280-8a1e-11ea-9e37-4725d62cdb3c.png)

*すべての基本フラグが表示されるよう設定されたプレイヤービュー。*

![消滅の呪い](https://user-images.githubusercontent.com/20014332/80591692-6799b500-8a1e-11ea-9ab8-e076f47d2220.png)

*フラグの1つに「消滅の呪い」が適用される。*

![隠されたフラグがたくさんある](https://user-images.githubusercontent.com/20014332/80591757-839d5680-8a1e-11ea-8864-83b09252a7b9.png)

*基本フラグのプレイヤービュー。「トラップドア」フラグが隠されている。*

### 設定パネルのカスタマイズ { #customizing-the-settings-panel }

!!! new "BentoBox 3.23.0で追加"
    設定パネルは、他の[カスタマイズ可能なGUI](/en/latest/Tutorials/generic/Customizable-GUI/)のようにテンプレートファイルでレイアウトされます。

設定パネルのレイアウトは`plugins/BentoBox/panels/settings_panel.yml`から読み込まれます。このファイルはBentoBoxの初回起動時に作成されます。ゲームモードアドオンは自身の`panels`フォルダーに独自のコピーを同梱でき（例：`plugins/BentoBox/addons/BSkyBlock/panels/settings_panel.yml`）、そのゲームモードではそちらが代わりに使用されます。デフォルトのファイルは以前のパネルをそのまま再現しているため、編集するまで何も変わりません。ファイルを読み込めない場合、BentoBoxはエラーをログに出力し、組み込みのパネルを表示します。

各ボタンは`data.type`で配置します：

| タイプ | 表示内容 |
| --- | --- |
| `TAB` | タブボタン。`data.tab`は`PROTECTION`、`SETTING`、または`WORLD_PROTECTION`（プレイヤーがアイランド上にいないときに表示される読み取り専用のビュー）です。該当しないタブは表示されず、代わりにボタンの`fallback`が使用されます。 |
| `FLAG` | ページ分けされたフラグ一覧の1スロット。1ページに表示したいフラグの数だけ配置します。`data.flag: <FLAG_ID>`を指定すると、そのスロットには常にそのフラグが表示され、そのフラグはページ一覧から外れます。ロックアイコンや設定変更アイコンはこの方法で配置されています。 |
| `MODE` | 表示モードの切り替え。`data`内の`basic-icon`、`advanced-icon`、`expert-icon`でモードごとにアイコンを設定できます。 |
| `RESET` | すべてのフラグをデフォルトに戻します。アイランドのオーナーにのみ表示されます。 |
| `NEXT`、`PREVIOUS` | ページ送り。移動先のページがある場合にのみ表示されます。 |

**タイトルとタブ名は別々です。** パネルのタイトルはテンプレートの`title`で、デフォルトはロケールエントリー`panels.settings.title`です。これは`[tab]`（表示中のタブの名前）と`[world_name]`を置き換えて翻訳されます。デフォルトは`[tab]`のみです。各タブボタンには独自の`title`と`description`があり、デフォルトは`protection.panel.PROTECTION.title`などのエントリーです。そのため、テンプレートまたはロケールのどちらでも、タイトルとタブボタンを別々のスタイルにできます。

**説明文（ロア）のレイアウト。** フラグの説明文は、ロケールの`protection.panel.flag-item.description-layout`（保護フラグ）、`setting-layout`（設定）、または`menu-layout`（サブパネルを開くフラグ）から組み立てられます。3.23.0以降、これらのレイアウトには`[ranks]`（保護フラグのランク一覧が挿入される位置）と`[tooltips]`（テンプレートのフラグボタンの`actions`のツールチップが挿入される位置）を含めることができます。`[ranks]`がない場合、ランク一覧は従来どおりレイアウトの後に追加されます。`[tooltips]`がない場合、ツールチップは空行の後に追加されます。クリックのヒントをランク一覧の下に移動するには、レイアウトからヒントを削除し、`[ranks]`と`[tooltips]`を好きな位置に置き、テンプレートの`flag_button`でヒントをツールチップとして宣言します。テンプレート内のフラグボタン自身の`title`と`description`で別のロケールエントリーを指定すると、そのパネルでのみ名前と説明文のレイアウトとして使用されます。

### コマンドランク { #command-ranks }

設定タブ上の**コマンドランク**アイコンを開くと、アイランド所有者が各チームコマンド（例えば招待、キック、アイランド名の設定など）を使用できる最低[ランク](#ranks)を選択できるパネルが開きます。保護フラグと同様に、**左**と**右クリック**でランクを循環させます。オペレーターは++shift+left-button++で[フラグを隠す](#hide-flags)のと同じ方法でプレイヤーからコマンドを隠せます。

BentoBox 3.23.3以降、プレイヤーは自分が実行権限を持つコマンドのみ表示されます。サーバーでコマンドのパーミッション（例えば`[gamemode].island.border`）を拒否した場合、そのコマンドはこのパネルにも表示されなくなります。以前はトップレベルコマンドのみチェックされていたため、プレイヤーが実行できないサブコマンドが引き続きリストされていました。

#### コマンドランクパネルのカスタマイズ { #customizing-the-command-ranks-panel }

!!! new "BentoBox 3.23.3で追加"
    コマンドランクパネルは、[設定パネル](#customizing-the-settings-panel)のようにテンプレートファイルでレイアウトされます。

レイアウトは`plugins/BentoBox/panels/command_ranks_panel.yml`から読み込まれます。このファイルはBentoBoxの初回起動時に作成されます。ゲームモードアドオンは自身の`panels`フォルダーに独自のコピーを同梱でき、そちらが代わりに使用されます。デフォルトのファイルはパネルの見た目を以前のまま保持しています：各コマンド用のマップ、フィラーなし、コマンドが必要なだけの行のみ。ファイルを読み込めない場合、BentoBoxは組み込みパネルを表示します。

各ボタンは`data.type`で配置します：

| タイプ | 表示内容 |
| --- | --- |
| `COMMAND` | ページ分けされたコマンド一覧の1スロット。1ページに表示したいコマンドの数だけ配置します。デフォルトは45です。 |
| `NEXT`、`PREVIOUS` | ページ送り。移動先のページがある場合にのみ表示されます。 |

組み込みパネルは49個のコマンドまでで、それ以降のコマンドは表示されませんでした。テンプレートはその代わりにページングされます。

テンプレートの`reusable`セクションの`command_button`でコマンドの描画方法を変更できます：

- `icon`はデフォルトの`MAP`を置き換えます。
- `title`は`protection.panel.flag-item.name-layout`の代わりに名前レイアウトとして使用するロケールエントリー（またはテキスト）です。`[name]`はコマンド（例：`/island sethome`）です。
- `description`は`protection.panel.flag-item.description-layout`の代わりに説明文レイアウトとして使用するロケールエントリー（またはテキスト）です。`[description]`は`protection.panel.flag-item.command-instructions`のコマンドのテキストです。ランク一覧がその後に追加されます。
- `actions`はツールチップのみを追加し、ランク一覧の後に追加されます。クリック自体は常に上記の通り機能します。デフォルトレイアウトには既にクリックヒントが含まれています。

例えば、各コマンドを紙として表示し、空のスロットを埋めるには：

```yaml
command_ranks_panel:
  title: protection.flags.COMMAND_RANKS.name
  type: INVENTORY
  background:
    icon: LIGHT_BLUE_STAINED_GLASS_PANE
    title: "&b&r"
  force-shown: 6
  content:
    # ... rows of command_button, and the paging buttons, as in the default file
  reusable:
    command_button:
      icon: PAPER
      data:
        type: COMMAND
```

## 管理者設定パネル { #admin-settings-panel }

ゲームワールド内で**引数なしで**`/[admin_command] settings`を実行して、**管理者設定パネル**を開きます（パーミッション`[gamemode].admin.settings`）。3つのタブがあります。これらは既存のアイランドではなく、ワールドと新規アイランドをコントロールします。

!!! tip
    各ゲームモードには独自の管理コマンドと独自の設定があります。変更したいゲームモードのコマンドを実行してください。例えばBSkyBlockの場合は`/bsbadmin settings`、AcidIslandの場合は`/acid settings`です。

!!! new "BentoBox 3.23.0で追加"
    管理者設定パネルは、[プレイヤーの設定パネル](#customizing-the-settings-panel)と同じ方法で`plugins/BentoBox/panels/admin_settings_panel.yml`でレイアウトされます。そのタブタイプは`WORLD_SETTING`、`WORLD_DEFAULTS`、`ISLAND_DEFAULTS`です。最後の2つは`[gamemode].admin.set-world-defaults`パーミッションが必要で、なければ隠されます。同じファイルは`/[admin_command] settings <player_name>`をレイアウトします。各ワールドタブはアイランドタブ（`PROTECTION`、`SETTING`）を`fallback`として指定します。これはアイランドがあるときに表示されるものです。

これらのタブで行われた変更は、ゲームモードの`config.yml`にすぐに保存されます。

### ワールド設定 { #world-settings }

最初のタブには**ワールド設定**フラグがリストされます：*クリーパーダメージ*、*オフラインレッドストーン*、*訪問者はインベントリを保持*など、ゲーム全体のオン/オフスイッチです。フラグをクリックしてオン/オフを切り替えます。各フラグはパーミッション`[gamemode].admin.world.settings.<FLAG_ID>`が必要です。オペレーターは持っています。

ワールド設定はコンソールまたはチャットからも設定できます：

```
/[admin_command] settings <FLAG_ID> <Active|Disabled>
```

!!! new "BentoBox 3.23.6で追加"
    **常に許可するエンティティタイプ**アイテム（鉄インゴット）を開くと、すべての生物エンティティタイプのリストが表示されます。緑色のタイプは、動物またはモンスターのスポーンがオフでも、どのアイランドまたはワールドでもスポーンします。アイアンゴーレムはデフォルトでは緑色なので、村のアイアンゴーレムトラップは動作し続けます。**グローバルモブスポーン**ブロックリストは引き続き優先されます。リストはゲームモードの`config.yml`ではなくBentoBoxで保存されます。[モブスポーンの優先順位](#mob-spawning-precedence)を参照してください。パーミッション`[gamemode].admin.settings.ALLOW_MOBS`が必要です。

#### 各ワールド設定の説明 { #what-each-world-setting-does }

多くのサーバーで確認しておきたいワールド設定です。デフォルト値は BSkyBlock のものです。ほかのゲームモードでは異なる場合があります。すべてのフラグは[フラグ](Flags.md)に一覧があります。

| 設定 | 機能 | デフォルト |
|---|---|---|
| **常に許可するエンティティタイプ** | 動物やモンスターのスポーンフラグの設定に関係なく、アイランドとワールドでスポーンするエンティティです。動物のスポーンをオフにしたサーバーやアイランドで、村のアイアンゴーレムトラップを動作させるために使います。アイアンゴーレムはデフォルトで許可されています。ブロックリスト（*グローバルなモブスポーン*）が引き続き優先されます。[モブスポーンの優先順位](#mob-spawning-precedence)を参照してください。 | アイアンゴーレム |
| **チェストの爆発ダメージ** | 爆発（クリーパー、TNT、ウィザー、ガスト）によるチェストの破壊を保護します。グリーフを防ぎますが、チェストを使って爆発防止部屋を作ることができます。 | オン |
| **スーパーフラットのクリーン** | ワールドジェネレーターが停止すると、新しいチャンクがフラットな草として生成されます。この設定はそれらのチャンクを検出して修復します。この問題がある場合を除いてオフにしてください。リソースが集約的です。 | オフ |
| **荒い土の耕作** | プレイヤーがクワを使って荒い土を通常の土に変換することを防ぎます。ほとんどのゲームモードで土は貴重ですが、砂利が簡単に入手できる場合、荒い土の耕作を悪用してそれを安価に生成できます。 | オフ（防止オン） |
| **クリーパーの爆発** | クリーパーの爆発によるアイランドブロックへのダメージを防ぎます。クリーパーはアイランド破壊の最も一般的な原因です。これを防ぐとゲームが簡単になりますが、管理者のサポート負担が軽減されます。 | オン |
| **クリーパービジター点火** | 他人のアイランドでビジターがクリーパーをプライムするためにフリント&鋼を使用することを防ぎます。これはよくあるグリーフ方法です。 | オン |
| **エンダーチェスト** | ゲームモードのワールド間でアイテムを密輸できるエンダーチェストへのアクセスと作成をブロックします。ワールド別エンダーチェストプラグインを使用する場合は無効にしてください。 | オン（ブロック） |
| **エンダーマンのブロック盗難** | エンダーマンがアイランドからブロックを拾うことを防ぎます。これがないと、プレイヤーが自分では取り除いていないブロックを失うことになります。 | オン |
| **モブの地理的制限** | 特定のモブ（例：ウィザー、飛行モブ）がスポーンしたアイランドを離れるのを防ぎます。境界を越えると削除されます。 | オン |
| **ビジター保護** | ビジターを他のプレイヤーのアイランドでほとんどの種類のダメージから保護します。ビジターが虚空に落ちた場合も安全な場所にテレポートします。 | オン |
| **アイテムフレーム保護** | 非メンバーによるアイテムフレームの破壊やアイテムのノックアウトを防ぎます。 | オン |
| **グローバルモブスポーン** | ワールド内どこでもスポーンできるモブタイプを設定し、他のすべてのスポーン設定を上書きします。例：ファントムをサーバー全体で無効化します。 | 様々 |
| **アイランド外の液体フロー** | 溶岩と水がアイランド保護境界を越えて流れるのを停止し、アイランド間の丸石形成や洪水を防ぎます。 | オン |
| **アイランド外のモブスポーン** | アイランド間のエリアでモブがスポーンするのを防ぎ、スポーンをアイランドゾーン内に集中させます。AcidIslandでは不自然に見えるため推奨しません。 | オフ |
| **黒曜石のすくい取り** | 孤立した1つの黒曜石ブロックを空のバケツで右クリックして溶岩を回収できます。丸石ジェネレーターのセットアップ中に誤って黒曜石を作った新しいプレイヤーを助けます。 | オン |
| **オフライン植物成長** | ビジターがチャンクをロードしていても、チームメンバーがオンラインでないときにアイランドで作物や植物が育つのを停止します。 | オフ |
| **オフラインレッドストーン** | チームメンバーがオンラインでないときにアイランドのレッドストーン回路を無効にします。 | オフ |
| **境界外ピストン** | ピストンがアイランドの保護境界を越えてブロックを押し出すのを停止します。隣接するアイランドへのグリーフの一般的な悪用手段です。 | オン |
| **テレポート時のモブ削除** | プレイヤーがアイランドホームにテレポートする際に周囲の敵対モブをクリアし、到着時の不意打ちによる死を防ぎます。 | オン |
| **スポーナータイプ保護** | プレイヤーがスポーンエッグを使ってスポーナーブロックのモブタイプを変更するのを防ぎます。スポーナーが報酬として与えられる場合に便利です。 | オン |
| **木の成長境界** | 木がアイランドの保護境界を越えて成長するのを防ぎます。これがないと、木が他のアイランドに侵入したり、届かないブロックが作られたりすることがあります。 | オン |
| **ウィザーダメージ** | ウィザーがアイランド上および間で引き起こす破壊を制限します。 | オン |

#### モブスポーンの優先順位 { #mob-spawning-precedence }

自然スポーンとスポナーによるモブのスポーンは、次の順序で判定されます。最初に一致したルールが優先されます。

1. **グローバルなモブスポーン**のブロックリスト（ゲームモード設定の`protection.block-mobs`）。ブロックされたタイプは決してスポーンしません。
2. **常に許可するエンティティタイプ**の許可リスト。許可されたタイプは、以下のフラグに関係なくスポーンします。
3. アイランドの**動物の自然スポーン**、**モンスターの自然スポーン**、**動物スポナーのスポーン**、**モンスタースポナーのスポーン**の設定。アイランドがない場合は、それらのフラグのワールドのデフォルト。

繁殖、スポーンエッグ、ゴーレムの作成など、プレイヤーが直接引き起こしたスポーンは、これらのいずれによっても制限されません。

!!! note "許可リストの保存場所"
    他のワールド設定とは異なり、許可リストはゲームモードの`config.yml`にはありません。BentoBoxがゲームモードごとに1つのレコードとして自身のデータベースに保存します。デフォルトのフラットファイルデータベースでは`plugins/BentoBox/database/CoreWorldSettings/<GameMode>.json`です。ゲームモードが初めて認識されたときに`IRON_GOLEM`で初期化され、それ以降はパネルでの管理者の編集のみが適用されます。レコードを削除すると初期状態に戻ります。


### ワールド保護 { #world-protections }

2番目のタブ**ワールド保護**は、プレイヤーが**どのアイランドの保護範囲外でも**何をできるかを決定します。アイランド間のボイド、アイランドでないスポーンエリア、荒地を含みます。[アイランドの終わり](#where-an-island-ends)を参照してください。

アイランド外ではチームもランクもないため、ここの各保護フラグは**全員のオン/オフ**です。フラグをクリックして切り替えます：

- **許可**：誰もがアイランド外でアクションを実行できます。
- **許可しない**：誰もできません。[バイパスパーミッション](#bypass-the-protection)を持つオペレーターとプレイヤーを除いて。

ほとんどの保護フラグはデフォルトでアイランド外では**許可しません**。プレイヤーは自分のアイランドの外でビルド、ブロックの破壊、アイテムの使用ができません。このタブは`[gamemode].admin.set-world-defaults`が必要で、各フラグはまた`[gamemode].admin.world.settings.<FLAG_ID>`が必要です。オペレーターは両方持っています。値はゲームモードの`config.yml`の`world.flags`の下に保存されます。

!!! example "プレイヤーにアイランド間の橋を構築させる"
    プレイヤーは自分のアイランドの上でのみ構築できるため、隣人への橋は構築できません。オフアイランドでの構築を許可するには：

    1. ゲームワールドに立って、プレイヤー名なしで`/[admin_command] settings`を実行します。
    2. **ワールド保護**タブを開きます。最初のタブでも**アイランドデフォルト**でもありません。
    3. **ブロックの設置**と**ブロックの破壊**、およびバケット、ドア、圧力板など、プレイヤーが外で必要とするその他のことをオンにします。

    アイランド自体は独自の設定で保護されたままです。訪問者が他のアイランドから物を取ることもできるようにするには、新規アイランドの[アイランドデフォルト](#island-defaults)を設定するか、`/[admin_command] settings <player>`で既存のアイランドを変更します。

アイランドを持たないプレイヤーは、`/[player_command] settings`でこれらの値（読み取り専用）を見ることができます。[ワールド保護ビュー](#world-protection-view)を参照してください。

### アイランドデフォルト { #island-defaults }

!!! new "BentoBox 3.14.0で追加"
    **アイランドデフォルト**タブは**新規作成されるアイランド**が開始するフラグを設定します。以前は、これはゲームモードの`config.yml`でのみ可能でした。

3番目のタブは**新規アイランド**のすべてのフラグの開始値を設定します：

- 各**保護フラグ**はそのデフォルトランクを表示します。左クリックまたは右クリックでランクを循環させます。
- 各**設定フラグ**はそのデフォルトのオン/オフ状態を表示します。クリックして切り替えます。

これらの値はゲームモードの`config.yml`の`world.default-island-flags`と`world.default-island-settings`に保存されます。そこにリストされていないフラグはフラグの組み込みデフォルトを使用します。

変更は**その後に作成された**アイランドにのみ適用されます。デフォルトを**既存の**アイランドにプッシュするには、`/[admin_command] resetflags`を実行してすべてのアイランドのすべてのフラグをリセットするか、`/[admin_command] resetflags <FLAG_ID>`で1つのフラグをリセットします。これはアイランド所有者が設定したものを上書きするため、確認を求められます。

このタブは**アイランド外**でプレイヤーが何をできるかをコントロール**しません**。そのためには、[ワールド保護](#world-protections)を使用してください。

### プレイヤーのアイランドを変更する { #changing-a-players-island }

`/[admin_command] settings <player_name>`を開くと、そのプレイヤーのアイランドの保護フラグと設定タブが表示されます。所有者が表示するようにです。管理者は任意のフラグを変更できます。`/[admin_command] settings spawn-island`はスポーンアイランドに対して同じことをします。

コマンドラインからも同じことができます：

```
/[admin_command] settings <player_name> <FLAG_ID> <rank>              # protection flag, e.g. Visitor
/[admin_command] settings <player_name> <FLAG_ID> <Active|Disabled>   # setting flag
```

## 保護のバイパス { #bypass-the-protection }

保護フラグはBentoBoxゲームワールド内でのみ適用され、それを正当に通り抜ける方法がないプレイヤーに対してのみ適用されます。保護をバイパスする方法はいくつかあります。一部は意図的（アイランドランク）、一部はスタッフ向け（オペレーターステータスと管理パーミッション）、一部は構造的（ワールドまたはフラグタイプ）です。

!!! tip
    下記のパーミッションの`[gamemode]`はゲームモードの小文字の名前です。BSkyBlockの場合はノードは`bskyblock.mod…`で始まり、AcidIslandの場合は`acidisland.mod…`です。

### アイランドランク — 本来の方法 { #island-ranks-the-intended-way }

保護フラグを「バイパス」する通常の設計方法は、アイランドで十分高い**ランク**を持つことです。すべての保護フラグは必須ランクを持ち、そのランク以上のランクを持つメンバーはアクションを実行できます。所有者がビルドでき、訪問者ができないのはこのためです。これは本当のバイパスではなく、設定通りにフラグが機能しているだけです。上記の[ランク](#ranks)リストを参照してください。

### オペレーター { #operators }

サーバーオペレーター（`/op`）は最も広範なバイパスです。OpはすべてのBentoBoxワールドの**すべての保護フラグ**を通過し、ロックされたアイランドやバンされたアイランドに入ることができ、バンまたは追放から免除されます。

2つの重要な注意点があります：

- **Opはアイランド設定フラグをバイパスしません。** `SETTING`タイプのフラグ（*PVP許可*、*モブスポーン*など）はオペレーターチェックの前に評価されるため、opは他のプレイヤーと同じように対象となります。オペレーターステータスは**保護**フラグのみをオーバーライドします。
- **管理スイッチはプレイヤーを自分のアイランドで完全に「非op」にすることはできません。** スイッチがオンであっても（下記を参照）、ランクチェックはオペレーターステータスを常に許可として扱うため、opはアイランドで引き続き許可されます。保護を本当の非opでテストするには、オペレーターステータスを削除します。

### 管理者バイパスパーミッション { #moderator-bypass-permissions }

フルオペレーターでは**ない**スタッフの場合、パーミッションの代わりに保護をバイパスできます。これらは管理スイッチでゲートされている（下記を参照）ため、管理者は独自のバイパスをオフに切り替えて、通常のプレイヤーとしてワールドを体験できます。

- `[gamemode].mod.bypassprotect` — ワールド中の**すべての**保護フラグをバイパスします。
- `[gamemode].mod.bypass.<FLAG_ID>.everywhere` — ワールド中の**1つの**名前付きフラグ（例：`BREAK_BLOCKS`）をバイパスします。
- `[gamemode].mod.bypass.<FLAG_ID>.island` — **1つの**名前付きフラグをバイパスしますが、プレイヤーがアイランド上で他の方法でブロックされる場合のみ。

### 管理「スイッチ」 — 通常のプレイヤーとしてテスト { #the-admin-switch-testing-as-a-normal-player }

コマンド`/[admin_command] switch`（パーミッション`[gamemode].mod.switch`）は管理者のバイパスパーミッションをオン/オフに切り替えます。デフォルトではバイパスパーミッションが**アクティブ**です（管理者が保護をバイパスしています）。コマンドを1回実行するとバイパスを**オフ**にして、通常のプレイヤーのように保護の対象となります。もう一度実行するとバイパスが戻ります。これは上記の`mod.bypassprotect`と`mod.bypass.*`パーミッションに影響します。生のオペレーターステータスを無効にするのは**ありません**。

### ロック、バン、追放 { #locks-bans-and-expels }

アイランドロック、バン、追放には、フラグシステムとは別の独自のバイパスパーミッションがあります：

- `[gamemode].mod.bypasslock` — ロックされたアイランドに入ります。
- `[gamemode].mod.bypassban` — バンされたアイランドに入ります。
- `[gamemode].mod.bypassexpel`と`[gamemode].admin.noexpel` — 追放されません。
- `[gamemode].admin.noban` — バンされません。

Bukkit `NPC`メタデータを持つすべてのエンティティ（例えばCitizens NPC）は、ロック、バン、PVP、無敵訪問者チェックを通り抜けることも許可されるため、プラグインNPCはアイランド保護に捕捉または被害を受けることはありません。

### クールダウンと遅延 { #cooldowns-and-delays }

コマンドクールダウンとテレポートウォームアップ遅延は以下でスキップできます：

- `[gamemode].mod.bypasscooldowns` — コマンドクールダウンを無視します。
- `[gamemode].mod.bypassdelays` — 遅延テレポートコマンドの移動ウォームアップ遅延をスキップします。

### 保護されないもの { #what-is-never-protected }

- **非BentoBoxワールド。** 保護はゲームモードワールド（とそのリンクされた標準ネザー/エンド）にのみ存在します。サーバーのデフォルトワールドと他のプラグインのワールドはチェックされません。
- **オフアイランドエリアは異なるルールに従います。** プレイヤーがゲームモードワールドにいるがすべてのアイランドの保護範囲外にある場合、アイランドのフラグの代わりに[ワールド保護](#world-protections)が適用されます。
- **削除されたアイランドは例外です。** 削除保留中のアイランド上では、デフォルトでは何も許可されません。`mod.bypassprotect` / `mod.bypass.<FLAG_ID>.everywhere`パーミッションを持つオペレーターと所有者を除いて。バイパスが最初にチェックされます。

## トラブルシューティング { #troubleshooting }

**プレイヤーはアイランド間でビルドまたはブロックを破壊できません。**
そのエリアはオフアイランドなので、[ワールド保護](#world-protections)タブが適用されます。そこで必要なフラグをオンにします。アイランドデフォルトを変更しても役に立ちません。

**アイランドデフォルトを変更しましたが、既存のアイランドは変更されませんでした。**
アイランドデフォルトはその後に作成されたアイランドにのみ適用されます。`/[admin_command] resetflags`を使用して既存のアイランドに適用するか、`/[admin_command] settings <player>`で1つのアイランドを変更します。

**プレイヤーはアイランドを所有しているのに設定を変更できません。**
設定は`[gamemode].settings.<FLAG_ID>`パーミッションが必要か、設定はクールダウン中である可能性があります。

**オペレーターですが、保護が機能するかテストできません。**
オペレーターはすべての保護フラグをバイパスします。非opアカウントでテストします。`/[admin_command] switch`は管理者バイパスパーミッションのみをオフにし、オペレーターステータスではありません。

**どのフラグがアクションをブロックしているかわかりません。**
`/[admin_command] why <player>`を実行して、そのプレイヤーのすべての保護チェックをコンソールにログしてから、アクションを実行します。ログはフラグ、位置、結果を表示します。コマンドをもう一度実行して停止します。
